# SPEC — unmute v1 compiler core (Load → Build → Validate)

Source of truth for the schema: [SCHEMA.md](../../SCHEMA.md) (locked v1). Reasons/research: [ORCHESTRATOR_SHARED_CONFIGURATION.md](../../ORCHESTRATOR_SHARED_CONFIGURATION.md). When code and SCHEMA.md disagree, SCHEMA.md wins (CLAUDE.md).

Scope of THIS spec: the target-independent core — `spec.Load → ir.Build → ir.Validate` — plus jsonschema-go schema derivation, the per-target capability-gating engine, and the shared **generation socket** (the `Generate` dispatch function and the rule that generation only runs after a clean validate). The five per-target emitters live in sibling driver specs, each consuming this core:

- [driver-pipecat.md](driver-pipecat.md) — code target
- [driver-livekit.md](driver-livekit.md) — code target
- [driver-deepgram.md](driver-deepgram.md) — code target (session bridge)
- [driver-vapi.md](driver-vapi.md) — managed target
- [driver-elevenlabs.md](driver-elevenlabs.md) — managed target

## §G goal
Compile the SCHEMA.md v1 package (`agent.yaml` + `instructions.md` + `agents/` + `tasks/` + `tools/*.yaml` + `targets.yaml`) into a resolved, validated IR. `spec.Load` parses (line/col errors, strict), `ir.Build` resolves all cross-file references into typed structs that are the single source of truth (jsonschema-go derives the schema from them), `ir.Validate` gates every field against the chosen targets and fails loud in the provider's own words. Generation stays a separate step. Replaces the old `project.yaml` schema in `internal/{spec,ir,generate}`.

## §C constraints
- C1: Go only (ADR-0002, CLAUDE.md one rule). This spec emits nothing — Load→Validate only. No Python maintained, generated, or shelled out to in this scope.
- C2: IR structs in `internal/ir` are the single source of truth; `google/jsonschema-go` derives the JSON Schema from them via reflection (`For[T]()` / `ForType()`) — never hand-author a `.json` schema file (CLAUDE.md IR rule). Pin the exact jsonschema-go v0.x; bump deliberately. Three reflection limits shape the IR (verified 2026-07-15, corrected against v0.4.3 on 2026-07-15; see V2): (a) the resolved IR must hold cross-references as **names/IDs (strings), never embedded pointers**, so the struct graph stays acyclic — a pointer cycle (agent-transfer `A→B→A`) makes `For[T]` return "cycle detected"; (b) the `Control` union needs manual `ForOptions.TypeSchemas` (a `oneof` hook); (c) Go has no enum and jsonschema-go tags are descriptions only, so enum result types need a manual `TypeSchemas` override. Manual schema hooks for (b)/(c) are allowed and expected.
- C3: `spec.Load` uses `goccy/go-yaml` for line/col on parse errors. Strict decode — unknown fields are an error, never silently dropped. A field never silently does nothing (SCHEMA.md §1).
- C4: SCHEMA.md sections 4–7 are the human source of truth for the capability matrix (each field's `core|warn|gated|provisional` tag per target). The code's capability table (I.capability) is the *machine form*; when the two disagree, SCHEMA.md wins — fix the table. It lives in its own **leaf package `internal/target`** (imported by both `ir` and `generate`), so each driver can own its provider's rows without an import cycle — `generate → ir` is one-way, so a table inside `ir` could never accept driver-contributed rows. Do NOT restate the whole matrix as prose in this spec.
- C5: cobra rules (CLAUDE.md): `newRootCmd()`, `RunE`, write via `cmd.OutOrStdout()`/`cmd.ErrOrStderr()`, no `os.Exit`/`log.Fatal` in commands, errors wrapped `%w`, `SilenceUsage`+`SilenceErrors`. Warnings → stderr, exit 0. Gated errors → exit 1.
- C6: tag → behavior mapping is the spine (SCHEMA.md §1, D3): `core` never fails; `warn` → stderr + exit 0, artifact still valid, never a silent downgrade; `gated` → hard error BEFORE any artifact, message in the failing provider's own vocabulary; `provisional` → fails on every target until a driver proves it. Multi-target: fail if ANY resolved target rejects.
- C7: the old `project.yaml` schema in `internal/ir` + `internal/spec` + the old `internal/generate` consumers models a different product (concrete model names, deploy/GPU/Docker knobs, Twilio specifics — D10/D11/D12 inverted). The v1 pipeline supersedes it. Cutover is **phased, never a big-bang delete**: the old emitters (`generate/{pipecat,slng}.go`) and the commands using them keep working until at least one new driver `case` is real — otherwise `compile`/`apply`/`dev` emit nothing for the whole multi-driver build window (T10 ships the driver `case`s as stubs). `init`/scaffold must be rebuilt to emit the v1 package layout — its own task (T11), or it is left dangling. `examples/safe_core/` is the v1 golden fixture.
- C8: two target groups drive all gating (SCHEMA.md intro, D4 pattern rule): **code targets** LiveKit, Pipecat, Deepgram (Unmute owns generated code, can build a missing feature); **managed targets** Vapi, ElevenLabs (provider runs the agent, only its API surface is usable). Deepgram is a code target (session bridge), not managed.
- C9: no secrets in any package file (D12). `targets.yaml` carries env var names and secret references only. Loader forwards references; it never reads or requires secret values.
- C10: all names lowercase snake_case; leading underscore is reserved by providers → rejected (N8). Tools and controls share ONE namespace (D8). Durations use Go syntax (`90s`, `15m`, `1h30m`).
- C11: bindings and `params` are forwarded verbatim, never validated (D2/D10, SCHEMA.md §6.2). The compiler checks completeness + structure only, and lists every forwarded binding/param in the report so what was sent is inspectable (rule 6). Model/voice identities and param values are relayed; provider API + generated project are the real validators.
- C12: `capacity` is declared; worker/GPU/quota numbers are derived and printed in the report, never stored in the package (D11, N2). Sizing coefficients are dated and marked `unbenchmarked` until measured.

## §I surfaces
- I.package: on-disk v1 layout (SCHEMA.md §3): `agent.yaml`, `instructions.md`, `agents/*.md`, `tasks/*.md`, `tools/<name>.yaml` (+ `<name>.py` handlers, code targets only), `targets.yaml`. Tool name = its file name (N4); no `name:` field inside the file.
- I.spec.Load: `internal/spec` — `Load(dir string) (*spec.Package, error)`. `goccy/go-yaml` strict decode of every package file with file:line:col errors. Returns raw decoded structs; NO cross-file resolution. Reads markdown prompt bodies by path.
- I.ir.types: `internal/ir` — v1 constructs as Go structs mirroring SCHEMA.md §4–6: `Agent` (top level), `Pipeline{Listen,Turn,Speak}` with `placement`/`semantic_endpointing`, `ModelProfile`/`VoiceProfile` (abstract, `placement`+`fallback`), `Variable` (`type`/`default`/`source`), `AgentDef`, `Task`, `TaskGroup`, `Control` (`Delegate|AgentTransfer|HumanTransfer`), `Tool` (`description`, `input`/`output`, `execution`, `handler` iff `local`, `url_env` iff `webhook`, `interruption`, `effect`), `Conversation` (`greeting`/`interruption`/`inactivity`/`max_duration`/`thinking_audio`), `Channel`, `Capacity`, `Target` (incl. `destinations` map for `human_transfer` resolution, §6.1), `Binding`. All cross-references are stored as **names, not pointers** (C2, keeps the graph acyclic). jsonschema-go derives the schema from these, with manual `TypeSchemas` overrides for the `Control` union and enum result types (C2).
- I.ir.Build: `internal/ir` — `Build(*spec.Package) (*ir.Agent, error)`. Resolves every reference (entry_agent; agent `model`/`voice` → profiles; tool + control names; `task`/`group` names; `then_target`; `fallback` chains; `summarizer`; `requires` variables; `destination`). Flattens + cycle-checks fallback. Enforces snake_case + reserved-underscore + shared-namespace uniqueness. Returns the resolved IR.
- I.capability: `internal/target` (leaf package, C4) — the machine form of the SCHEMA.md §4–7 matrix. Not one scalar map but a small set of **typed per-provider matrices**, because Validate needs more than a tag: (a) the tag matrix `(field, provider) → core|warn|gated|provisional` + condition note; (b) the role matrix `(role, provider) → open|integrated` (§6.2, for V9); (c) the history matrix `(history-value, provider) → ok|fail|generated` (§4.7, for V8); (d) the fallback slot-kind per provider (for V10). One place; the gating engine reads only this. Condition notes carry provider vocabulary (e.g. "Vapi: return-to-prior-assistant unverified") — a deliberate trade: `internal/target` is provider-aware even though `ir` is not.
- I.ir.Validate: `internal/ir` — `Validate(*ir.Agent, targets []ir.Target, caps target.Table) (ValidateReport, error)`. Structural checks (SCHEMA.md rules 1–3, 9, 12) + tier gating (rule 4) + context policy (rule 5) + capability gating (C6) against each resolved target, reading the capability matrices from `caps` (supplied by the caller; `ir` does not import `internal/target` for data it can receive). Returns `ValidateReport{PerTarget []{Provider, Errors, Warnings}, ForwardedBindings, Sizing}` — a per-target pass/fail breakdown, not one flat list (V18).
- I.schema: **two derived schemas, from different structs.** The **authoring schema** is derived from the `spec.Package` decode structs (`internal/spec`) — that is the on-disk shape an editor validates as the user types (`instructions` is a path, tools are separate files, refs unresolved). A separate IR-derived schema (from `ir.Agent`) is for internal/debug use only; it is NOT the authoring surface (paths→text, refs flattened). Neither is a committed hand-authored file.
- I.cli.validate: `unmute validate <package-dir> [--target <name>...]` — runs Load→Build→Validate, prints a **per-target pass/fail matrix**, exit 0 (ok/warn-only across all) or 1 (any gated error). Cobra rules (C5). With no `--target`, validates against every instance declared in `targets.yaml`. Declaring a target instance is **opt-in to its gates** — adding a `deepgram` instance will (correctly) start failing a package that uses `mcp`/`outbound`; documented as a choice, not a surprise (V18).
- I.generate.Generate: `internal/generate` — `Generate(agent *ir.Agent, target ir.Target, caps target.Table) (Artifact, error)` dispatches on `target.Provider` to the per-target emitter (a `switch`, not an interface). The result carries an explicit discriminant: `Artifact{Kind: CodeTarget|ManagedTarget; Files []File; Apply *ApplyPlan; Notes GenerateReport}` — `CodeTarget` sets `Files` (a project on disk), `ManagedTarget` sets `Apply`. `ApplyPlan` is a **multi-step ordered plan** `Steps []ApplyStep{Method, Endpoint, Body, CaptureID, Branch}`, not a single endpoint+method — Vapi Squad synthesis needs N assistant-creates + a squad-create with id back-references, and ElevenLabs needs branch-aware apply. Credentials are env-named references only, never values (C9). `GenerateReport` (emit-time notes) is distinct from `ValidateReport` (gating). The dispatch runs `Validate` first and refuses to emit on any gated error (V17). Each driver spec owns exactly one `case`.

## §V invariants
- V1: every referenced name (`tools`, `controls`, `task`, `group`, `to`, `then_target`, `model`, `voice`, `fallback`, `requires`, `summarizer`, `destination`) resolves in Build; unresolved → error naming the missing name and its file:line. (rule 1)
- V2: the IR structs are the only schema source. jsonschema-go derives the schema from them by **runtime reflection** (`For[T]`, not codegen); no hand-authored `.json` schema exists. Adding a *plain* IR field changes the derived schema for free — with three exceptions that need manual hooks (C2): the `Control` union (`ForOptions.TypeSchemas`), enum result types (`TypeSchemas`), and cross-references, which must be stored as names not pointers to avoid a reflection cycle.
- V3: an unknown or misspelled YAML field → parse error with file:line:col — goccy supplies line:col, the loader prepends the filename (it reads many files). Never silently ignored; a field never silently does nothing.
- V4: a `gated` field on a target that cannot honor it → hard error before any artifact, message in that provider's own vocabulary (e.g. `history: messages` on ElevenLabs → "ElevenLabs always keeps the full transcript"). Multi-target: fails if ANY resolved target rejects.
- V5: a `warn` field on a warning target → message to stderr, exit 0, IR still valid; never a silent downgrade (SCHEMA.md §1, D3).
- V6: (forward-looking) a `provisional` field, when used, fails validation on every target until a driver clears its tag. No field in SCHEMA §4–6 currently carries `provisional`; this guards the tag for future use.
- V7: a name that is not lowercase snake_case, or starts with `_`, → rejected (N8). Tools and controls share one namespace; a name collision across them → error (D8).
- V8: `context.history` is required on every task and transfer; `max_messages` legal iff `last_n`; `summary` requires a declared+bound `summarizer` profile; `include_tool_calls: false`, variable-list subsets, and `context_scope: isolated` compile only on code targets — else gated error. (rule 5, §2.4)
- V9: bindings are checked for completeness + structure only, never for identity/param values: every open role and every used model/voice profile has a binding in each resolved target; an integrated-role binding carries settings only and never names an outside model; the binding's placement agrees with the profile's `placement`; a missing binding → error; forwarded params pass through untouched. (rule 12, §6.2)
- V10: fallback chains are flattened and cycle-checked; every profile in a chain lands in the same slot kind and placement on the resolved target; a cross-provider chain on Vapi → error. (§4.1)
- V11: tier gating resolves against the SCHEMA.md §4.6 tier conditions and the §7 feature matrix, driven by I.capability, not hardcoded per call site (e.g. single `tasks` fail on Vapi; `then: return` fails on Vapi; `task_group` warns on LiveKit).
- V12: `capacity.peak_sessions ≤ max_sessions`; both required when a telephony channel is present OR a code target is resolved; violation → error. (rule 9)
- V13: `outbound: true` telephony requires `on_voicemail` present AND all `source: call_start` variables satisfiable; Deepgram generates carrier-conditional voicemail handling with a warning (N6). (rule 8, §4.9)
- V14: `examples/safe_core/` loads, builds, and validates with zero gated errors on all five targets; only the warnings SCHEMA.md §7 permits may appear. It is the golden fixture.
- V15: the report lists every forwarded binding and param (so what was sent is inspectable) and marks every derived sizing number `unbenchmarked` until a dated coefficient exists. (§6.2 rule 6, §5.1)
- V16: `unmute validate` obeys cobra rules — `RunE`, writes via `cmd.OutOrStdout`/`cmd.ErrOrStderr`, no `os.Exit`, exit 1 on gated error and 0 on warn-only, in-process testable (L2), zero Python (L1–L3).
- V17: `generate.Generate` runs `Validate` and returns without emitting if any gated error is present; a warn-only validate still emits. No driver is reached for a target it fails on. (generation socket, C6)
- V18: `Validate` returns a per-target pass/fail breakdown; `unmute validate` prints every target's result and exits 1 if any is gated. Declaring a target instance opts a package into that target's gates — not a global all-or-nothing surprise.
- V19: an emitter cannot exceed its capability rows — a test asserts every `generate.Generate` provider `case` implements exactly the fields its `internal/target` rows mark supported, so a `core`/`warn` tag can never pass Validate for a field the emitter has no code path for (no validate-green / generate-broken drift).
