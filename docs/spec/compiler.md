# SPEC — unmute v1 compiler core (Load → Build → Validate)

Source of truth for the schema: [SCHEMA.md](../SCHEMA.md) (locked v1). Reasons/research: [ORCHESTRATOR_SHARED_CONFIGURATION.md](../ORCHESTRATOR_SHARED_CONFIGURATION.md). When code and SCHEMA.md disagree, SCHEMA.md wins (CLAUDE.md).

Scope of THIS spec: the target-independent core — `spec.Load → ir.Build → ir.Validate` — plus jsonschema-go schema derivation, the per-target capability-gating engine, and the shared **generation socket** (the `Generate` dispatch function and the rule that generation only runs after a clean validate). The four per-target emitters live in sibling driver specs, each consuming this core (the ElevenLabs driver spec was retired 2026-07-20, SCHEMA N17):

- [driver-pipecat.md](driver-pipecat.md) — code target
- [driver-livekit.md](driver-livekit.md) — code target
- [driver-deepgram.md](driver-deepgram.md) — code target (session bridge)
- [driver-vapi.md](driver-vapi.md) — managed target

## §G goal
Compile the SCHEMA.md v1 package (`agent.yaml` + `instructions.md` + `agents/` + `tasks/` + `tools/*.yaml` + `targets.yaml`) into a resolved, validated IR. `spec.Load` parses (line/col errors, strict), `ir.Build` resolves all cross-file references into typed structs, and `ir.Validate` gates every field against the chosen targets and fails loud in the provider's own words. jsonschema-go derives an authoring schema from the decode structs and a resolved/debug schema from the IR structs (I.schema). Generation stays a separate step. Replaces the old `project.yaml` schema in `internal/{spec,ir,generate}`.

## §C constraints
- C1: Go only (ADR-0002, CLAUDE.md one rule). This spec emits nothing — Load→Validate only. No Python maintained, generated, or shelled out to in this scope.
- C2: Go structs are the only schema sources for their own surfaces: decode structs in `internal/spec` author the unresolved authoring schema, and structs in `internal/ir` author the resolved/debug schema (I.schema). `google/jsonschema-go` derives both via reflection (`For[T]()` / `ForType()`) — never hand-author a `.json` schema file. Pin the exact jsonschema-go v0.x; bump deliberately. Three reflection limits shape the resolved IR (verified 2026-07-15, corrected against v0.4.3 on 2026-07-15; see V2): (a) the resolved IR must hold cross-references as **names/IDs (strings), never embedded pointers**, so the struct graph stays acyclic — a pointer cycle (agent-transfer `A→B→A`) makes `For[T]` return "cycle detected"; (b) the `Control` union needs manual `ForOptions.TypeSchemas` (a `oneof` hook); (c) Go has no enum and jsonschema-go tags are descriptions only, so enum result types need a manual `TypeSchemas` override. Manual schema hooks for (b)/(c) are allowed and expected.
- C3: `spec.Load` uses `goccy/go-yaml` for line/col on parse errors. Strict decode — unknown fields are an error, never silently dropped. A field never silently does nothing (SCHEMA.md §1).
- C4: SCHEMA.md sections 4–7 are the human source of truth for the capability matrix (each field's `core|warn|gated|provisional` tag per target). The code's capability table (I.capability) is the *machine form*; when the two disagree, SCHEMA.md wins — fix the table. It lives in its own **leaf package `internal/target`** (imported by both `ir` and `generate`), so each driver can own its provider's rows without an import cycle — `generate → ir` is one-way, so a table inside `ir` could never accept driver-contributed rows. Do NOT restate the whole matrix as prose in this spec.
- C5: cobra rules (CLAUDE.md): `newRootCmd()`, `RunE`, write via `cmd.OutOrStdout()`/`cmd.ErrOrStderr()`, no `os.Exit`/`log.Fatal` in commands, errors wrapped `%w`, `SilenceUsage`+`SilenceErrors`. Warnings → stderr, exit 0. Gated errors → exit 1.
- C6: tag → behavior mapping is the spine (SCHEMA.md §1, D3): `core` never fails; `warn` → stderr + exit 0, artifact still valid, never a silent downgrade; `gated` → hard error BEFORE any artifact, message in the failing provider's own vocabulary; `provisional` → fails on every target until a driver proves it. Multi-target: fail if ANY resolved target rejects.
- C7: the old `project.yaml` schema in `internal/ir` + `internal/spec` + the old `internal/generate` consumers models a different product (concrete model names, deploy/GPU/Docker knobs, Twilio specifics — D10/D11/D12 inverted). The v1 pipeline supersedes it. Cutover is **phased, never a big-bang delete**: the old emitters (`generate/{pipecat,slng}.go`) and the commands using them keep working until at least one new driver `case` is real — otherwise `compile`/`apply`/`dev` emit nothing for the whole multi-driver build window (T10 ships the driver `case`s as stubs). `init`/scaffold must be rebuilt to emit the v1 package layout — its own task (T11), or it is left dangling. `internal/testdata/safe_core/` is the v1 golden fixture.
- C8: two target groups drive all gating (SCHEMA.md intro, D4 pattern rule): **code targets** LiveKit, Pipecat, Deepgram (Unmute owns generated code, can build a missing feature); **managed target** Vapi (provider runs the agent, only its API surface is usable; ElevenLabs was the second managed target until SCHEMA N17, 2026-07-20). Deepgram is a code target (session bridge), not managed.
- C9: no secrets in any package file (D12). `targets.yaml` carries env var names and secret references only. Loader forwards references; it never reads or requires secret values. `tracing.provider: langfuse` selects emitted integration code only; its three credential values remain runtime environment variables.
- C10: all names lowercase snake_case; leading underscore is reserved by providers → rejected (N8). Tools and controls share ONE namespace (D8). Durations use Go syntax (`90s`, `15m`, `1h30m`).
- C11: model routes and `params` are forwarded verbatim, never validated (D2/D10 as amended, SCHEMA.md §6.2). The compiler checks completeness + structure only, and lists every forwarded model/param in the report so what was sent is inspectable (rule 6). Identities and param values are relayed; provider API + generated project are the real validators. One narrowing, and it is structural rather than a value check: the four **typed** generation fields must have a declared slot on the resolved entry (V36, N20). An author's `params` keys are untouched by that, including one spelled like a typed field.
- C12: `capacity` is declared; worker/GPU/quota numbers are derived and printed in the report, never stored in the package (D11, N2). Sizing coefficients are dated and marked `unbenchmarked` until measured.
- C13: telephony compilation is implemented only for LiveKit and Pipecat.
  Build resolves one Connection and one exact
  `(orchestrator, transport, carrier)` route per telephony target. Every v1
  route resolves shared coordination, a non-empty closed reason set, and Redis.
  Every reason maps to a declared consuming service; Redis is never an idle
  sidecar. LiveKit uses Redis for its Server/SIP control plane; generated
  Pipecat code uses it only for call correlation, callback idempotency,
  human-transfer state, and admission. Agent handoff, task state, transcripts,
  prompts, model context, and audio remain in the active worker. Sticky routing
  is not a correctness mechanism.

## §I surfaces
- I.package: on-disk v1 layout (SCHEMA.md §3): `agent.yaml`, `instructions.md`, `agents/*.md`, `tasks/*.md`, `tools/<name>.yaml` (+ `<name>.py` handlers, code targets only), `connections/<name>.yaml`, `targets.yaml`. Tool and Connection names come from their file names; neither has a `name:` field inside the file.
- I.spec.Load: `internal/spec` — `Load(dir string) (*spec.Package, error)`. `goccy/go-yaml` strict decode of every package file with file:line:col errors. Returns raw decoded structs; NO cross-file resolution. Reads markdown prompt bodies by path.
- I.telephony.connection: `connections/<name>.yaml` decodes to
  `Connection{Kind, Environment}`. `Environment` maps route-owned keys to
  environment variable names. The package contains no secret values and Load
  never reads the environment.
- I.telephony.route: Build resolves a LiveKit or Pipecat telephony target to
  one `TelephonyPlan`. The plan carries its exact route, directions, controls,
  variable sources, endpoints, evidence, admission owner, required environment
  names, manual steps, Compose application/dependency services,
  `coordination: shared`, and closed coordination reasons with deterministic
  consuming services. Validate and Generate consume this same plan.
- I.telephony.local: every telephony code route emits a deterministic
  `compose.telephony.yaml` plus provider-neutral service, health, and local
  environment facts in its runtime artifact. Every graph contains the generated
  application service and Redis. `livekit/sip/*` also selects LiveKit Server and
  LiveKit SIP.
- I.ir.types: `internal/ir` — v1 constructs as Go structs mirroring SCHEMA.md §4–6: `Agent` (top level; NO `Pipeline` struct, N15), `ModelDef` (one unified authoring type for every `models:` section entry + target overrides: `provider`, `model`, `voice`, `speed`, `language`, `temperature`, `top_p`, `top_k`, `params`, `fallback`, `placement` override, `semantic_endpointing`; kind — think/speak/listen/turn — is the section the entry sits in, fixed by Build and field-checked), `Variable` (`type`/`default`/`source`), `AgentDef`, `Task`, `TaskGroup`, `Control` (`Delegate|AgentTransfer|HumanTransfer`), `Tool` (`description`, `input`/`output`, `execution`, `handler` iff `local`, `url_env` iff `webhook`, `interruption`, `effect`), `Conversation` (`greeting`/`interruption`/`inactivity`/`max_duration`/`thinking_audio`), `Tracing` (`provider` only), `Channel`, `Capacity`, `Target`. `Target.Models` stays the **derived** `Bindings{Listen,Turn,Speak,Reason}` view (a `Binding` per effective model), which Build populates by resolving each target's overrides over the agent's `ModelDef`s — the generators and most of Validate consume this resolved view unchanged, so the unified `ModelDef` is an authoring-and-schema type, not a per-target one. (`Bindings`/`Binding` and the internal `reason` role identifier are retained deliberately: renaming a role that is no longer user-facing would be churn, N15.) All cross-references are stored as **names, not pointers** (C2, keeps the graph acyclic). jsonschema-go derives the authoring schema from `ModelDef` and the debug schema from the resolved IR, with manual `TypeSchemas` overrides for the `Control` union and enum result types (C2).
- I.ir.Build: `internal/ir` — `Build(*spec.Package) (*ir.Agent, error)`. Resolves every reference (entry_agent; agent `model`/`voice` → models, fixing each entry's kind from its reference site (V22); tool + control names; `task`/`group` names; `then_target`; `fallback` chains; `summarizer`; `requires` variables; `destination`). Flattens + cycle-checks fallback. Enforces snake_case + reserved-underscore + shared-namespace uniqueness. Returns the resolved IR.
- I.capability: `internal/target` (leaf package, C4) — the machine form of the SCHEMA.md §4–7 matrix. Not one scalar map but a small set of **typed per-provider matrices**, because Validate needs more than a tag: (a) the tag matrix `(field, provider) → core|warn|gated|provisional` + condition note; (b) the role matrix `(role, provider) → open|integrated` (§6.2, for V9); (c) the history matrix `(history-value, provider) → ok|fail|generated` (§4.7, for V8); (d) the fallback slot-kind per provider (for V10). One place; the gating engine reads only this. Condition notes carry provider vocabulary (e.g. "Vapi: return-to-prior-assistant unverified") — a deliberate trade: `internal/target` is provider-aware even though `ir` is not.
- I.ir.Validate: `internal/ir` — `Validate(*ir.Agent, targets []ir.Target, caps target.Table) (ValidateReport, error)`. Structural checks (SCHEMA.md rules 1–3, 9, 12) + tier gating (rule 4) + context policy (rule 5) + capability gating (C6) against each resolved target, reading the capability matrices from `caps` (supplied by the caller; `ir` does not import `internal/target` for data it can receive). Returns `ValidateReport{PerTarget []{Provider, Errors, Warnings}, ForwardedModels, Sizing}` — a per-target pass/fail breakdown, not one flat list (V18).
- I.schema: **two derived schemas, from different structs.** The **authoring schema** is derived from the `spec.Package` decode structs (`internal/spec`) — that is the on-disk shape an editor validates as the user types (`instructions` is a path, tools are separate files, refs unresolved). A separate IR-derived schema (from `ir.Agent`) is for internal/debug use only; it is NOT the authoring surface (paths→text, refs flattened). Neither is a committed hand-authored file.
- I.cli.validate: `unmute validate <package-dir> [--target <name>...]` — runs Load→Build→Validate, prints a **per-target pass/fail matrix**, exit 0 (ok/warn-only across all) or 1 (any gated error). Cobra rules (C5). With no `--target`, validates against every instance declared in `targets.yaml`. Declaring a target instance is **opt-in to its gates** — adding a `deepgram` instance will (correctly) start failing a package that uses `mcp`/`outbound`; documented as a choice, not a surprise (V18).
- I.generate.Generate: `internal/generate` — `Generate(agent *ir.Agent, target ir.Target, caps target.Table) (Artifact, error)` dispatches on `target.Provider` to the per-target emitter (a `switch`, not an interface). The result carries an explicit discriminant: `Artifact{Kind: CodeTarget|ManagedTarget; Files []File; Apply *ApplyPlan; Notes GenerateReport}` — `CodeTarget` sets `Files` (a project on disk), `ManagedTarget` sets `Apply`. `ApplyPlan` is a **multi-step ordered plan** `Steps []ApplyStep{Method, Endpoint, Body, CaptureID, Branch}`, not a single endpoint+method — Vapi Squad synthesis needs N assistant-creates + a squad-create with id back-references (`Branch` stays for a future managed driver that needs branch-aware apply). Credentials are env-named references only, never values (C9). `GenerateReport` (emit-time notes) is distinct from `ValidateReport` (gating). The dispatch runs `Validate` first and refuses to emit on any gated error (V17). Each driver spec owns exactly one `case`.

## §V invariants
- V1: every referenced name (`tools`, `controls`, `task`, `group`, `to`, `then_target`, `model`, `voice`, `fallback`, `requires`, `summarizer`, `destination`) resolves in Build; unresolved → error naming the missing name and its file:line. (rule 1)
- V2: the decode structs and IR structs are the only sources for their respective schemas (I.schema). jsonschema-go derives both by **runtime reflection** (`For[T]`, not codegen); no hand-authored `.json` schema exists. Adding a *plain* field changes its derived schema for free — with three resolved-IR exceptions that need manual hooks (C2): the `Control` union (`ForOptions.TypeSchemas`), enum result types (`TypeSchemas`), and cross-references, which must be stored as names not pointers to avoid a reflection cycle.
- V3: an unknown or misspelled YAML field → parse error with file:line:col — goccy supplies line:col, the loader prepends the filename (it reads many files). Never silently ignored; a field never silently does nothing.
- V27: Connection discovery is path-safe and strict. Missing files, duplicate
  names, unknown fields, invalid environment variable names, unknown target
  references, and missing or unknown route keys fail before generation.
- V28: telephony support is keyed by the exact route and feature. A match on
  only orchestrator, transport, or carrier cannot enable a direction, control,
  briefing mode, or system variable source. A route without a current official
  documentation URL, verification date, and successful smoke remains
  provisional.
- V29: every v1 telephony Compose file contains the generated application and
  version-pinned Redis. Exact route facts add only further dependencies:
  `livekit/sip/*` adds LiveKit Server and LiveKit SIP. No carrier choice removes
  Redis. At least one declared service consumes the Redis connection and gates
  readiness on it; an orphan Redis service is invalid. No carrier or model
  credential value is baked into the file or image.
- V30: `unmute dev --telephony` always executes the generated Compose graph and
  fails clearly when Docker Compose is unavailable. No flag enables or disables
  local telephony infrastructure; non-telephony dev behavior is unchanged.
- V31: Pipecat Redis records are TTL-bound and limited to pending-call
  correlation with the minimum call-start context, callback replay markers,
  human-transfer state/locks, and admission counters. Credentials, raw webhook
  bodies, audio, transcripts, prompts, model context, tasks, and agent handoff
  never enter Redis.
- V32: maintained Go code uses only standard-library APIs available at the
  module's `go` directive. The repository `go vet ./...` gate runs the
  `stdversion` analyzer and fails on a newer API before merge.
- V4: a `gated` field on a target that cannot honor it → hard error before any artifact, message in that provider's own vocabulary (e.g. `history: summary` on Vapi → "Vapi's contextEngineeringPlan has no summary mode"). Multi-target: fails if ANY resolved target rejects.
- V5: a `warn` field on a warning target → message to stderr, exit 0, IR still valid; never a silent downgrade (SCHEMA.md §1, D3).
- V6: (forward-looking) a `provisional` field, when used, fails validation on every target until a driver clears its tag. No field in SCHEMA §4–6 currently carries `provisional`; this guards the tag for future use.
- V7: a name that is not lowercase snake_case, or starts with `_`, → rejected (N8). Tools and controls share one namespace; a name collision across them → error (D8).
- V8: `context.history` is required on every task and transfer; `max_messages` legal iff `last_n`; `summary` requires a defined `summarizer` think model; `include_tool_calls: false`, variable-list subsets, and `context_scope: isolated` compile only on code targets — else gated error. (rule 5, §2.4)
- V9: effective models (agent.yaml definition unless a target override replaces the whole entry) are checked for completeness + structure only, never for identity/param values: every used model has an effective definition on each resolved target; `listen` present on every open-listen target; on an integrated role the effective entry carries settings only, never an outside model; placement derived from the route (`local/...`→local; explicit `placement:` overrides) gates against that target's capability rows; forwarded routes + params pass through untouched. (§6.2, N15)
- V10: fallback chains are flattened and cycle-checked; every model in a chain lands in the same slot kind and placement on the resolved target; a cross-provider chain on Vapi → error. (§4.1)
- V11: tier gating resolves against the SCHEMA.md §4.6 tier conditions and the §7 feature matrix, driven by I.capability, not hardcoded per call site (e.g. single `tasks` fail on Vapi; `then: return` fails on Vapi; `task_group` warns on LiveKit).
- V12: `capacity.peak_sessions ≤ max_sessions`; both required when a telephony channel is present OR a code target is resolved; violation → error. (rule 9)
- V13: `outbound: true` telephony requires `on_voicemail` present AND all `source: call_start` variables satisfiable; Deepgram generates carrier-conditional voicemail handling with a warning (N6). (rule 8, §4.9)
- V14: `internal/testdata/safe_core/` loads, builds, and validates with zero gated errors on all four targets (ElevenLabs removed 2026-07-20, N17); only the warnings SCHEMA.md §7 permits may appear. It omits tracing because Langfuse is unsupported on two of the four targets. It is the golden fixture.
- V15: the report lists every forwarded model and param (so what was sent is inspectable) and marks every derived sizing number `unbenchmarked` until a dated coefficient exists. (§6.2 rule 6, §5.1)
- V16: `unmute validate` obeys cobra rules — `RunE`, writes via `cmd.OutOrStdout`/`cmd.ErrOrStderr`, no `os.Exit`, exit 1 on gated error and 0 on warn-only, in-process testable (L2), zero Python (L1–L3).
- V17: `generate.Generate` runs `Validate` and returns without emitting if any gated error is present; a warn-only validate still emits. No driver is reached for a target it fails on. (generation socket, C6)
- V18: `Validate` returns a per-target pass/fail breakdown; `unmute validate` prints every target's result and exits 1 if any is gated. Declaring a target instance opts a package into that target's gates — not a global all-or-nothing surprise.
- V19: an emitter cannot exceed its capability rows — a test asserts every `generate.Generate` provider `case` implements exactly the fields its `internal/target` rows mark supported, so a `core`/`warn` tag can never pass Validate for a field the emitter has no code path for (no validate-green / generate-broken drift).
- V20 (added 2026-07-17, B4): docs↔catalogue sync — every vendor row in `docs/user/reference/providers.md` resolves through `Catalog.Lookup(framework, role, vendor)`, and every non-wildcard catalogue entry appears in that reference. A sync test parses the reference's provider tables and fails on either direction of drift, so deleting catalogue entries (B4's silent revert) or adding one without documenting it is a red build, never a silent narrowing of user-visible breadth.
- V21 (added 2026-07-17, B4): every catalogue entry carries a `Verified` date and a `Docs` URL; an entry missing either fails a unit test (`TestCatalogInvariants` already enforces this — recorded here so the check itself cannot be dropped in a refactor the way the entries were).
- V22 (added 2026-07-19, N15; sections+palette same day): `agent.yaml` is the only place a model is defined. No `pipeline` or `voices` blocks and no `targets.yaml` binding step exist; the decode structs have no removed fields, so an old-format file fails strict decode with file:line (V3). `models:` is four kind sections (`think`/`speak`/`listen`/`turn`) of `ModelDef`; kind is the section, fields are checked against it, and names are one namespace across sections (a duplicate → error). References must land in the right section (agent `voice:`→speak; agent/task `model:`/`summarizer:`/fallback→think; top-level `listen:`/`turn:` pointers→their sections); a reference without an entry, or into the wrong section, → error naming file:line. The map is a palette: unreferenced entries are legal alternates, never compiled or forwarded. The `listen`/`turn` selection defaults to a section's sole chain head (fallback-only entries are chain members, not candidates, T16); 2+ heads with no pointer → error naming the heads. A `targets.yaml` `models:` entry is a whole-entry replacement keyed flat by a defined name; an unknown key or a kind change → error; a target changes what a name means for itself, never which name is selected. Each entry keeps `provider` explicit (no route parsing); placement derives from `provider` (`local`→local; explicit `placement:` overrides). Build resolves each target's effective `ModelDef`s (override else agent def) for the USED set only into the derived `Target.Models` `Bindings` view, folding the typed generation fields (`temperature`/`top_p`/`top_k`/`speed`) into the binding's forwarded params, so every placement gate + sizing input + generator reads effective models per target.
- V24 (added 2026-07-19, B5): an agent references exactly its think model (`model:`) and speak model (`voice:`), plus `instructions` and `tools`; listen/turn references never appear on an agent — they are per-call plumbing selected at package level (one STT hears the whole call; the generated Pipecat main worker owns it, the Deepgram bridge has one listen per session). Strict decode rejects `listen:`/`turn:`/`vad:` inside an agent (V3), and `AgentDef` gains no such field without a new SCHEMA amendment. A future per-agent listen override (per-language agents) would be a new gated field, LiveKit/Vapi first, never a required authoring surface.
- V23 (added 2026-07-19, N15): scaffold emits one target instance named exactly the provider (`pipecat`, `livekit` — never a `-dev`/`-prod` suffix; `elevenlabs` dropped from the list 2026-07-20, N17). The scaffolded `agent.yaml` carries the concrete model definitions the wizard picked (unified `models:` map, plus `listen`/`turn` when the target needs them); the scaffolded `targets.yaml` carries infrastructure only and NO `models:` override block. Same package validates, compiles, and deploys unchanged — what you test is what you ship.
- V25 (added 2026-07-20): `agent.yaml` may carry one package-wide `tracing` object with exactly one field, `provider: langfuse`; it is not a list or generic module registry. Omission is valid and means no tracing integration. `spec.Load` strictly rejects unknown tracing fields; `ir.Build` rejects any provider other than `langfuse` and preserves the optional value in the target-independent IR; `ir.Validate` accepts it only for LiveKit and Pipecat and fails Vapi and Deepgram before generation. The capability table and every emitter agreement test include this field, so no target can validate green then ignore it.
- V26 (added 2026-07-20): `unmute init` omits `tracing` and Langfuse environment keys. All four public `examples/*` packages opt into Langfuse. The four-target `safe_core` fixture stays unconfigured (V14). This remains schema version 1; the migration for packages that want the former automatic output is one `tracing: { provider: langfuse }` block.
- V33 (added 2026-07-20, N16): no top-level `language` exists in the decode structs or the IR; `ModelDef.Language` is the only language knob, optional and BCP-47-validated per model. A generator fills a catalogue entry's language slot only when the effective model sets `language`; when unset, **no language kwarg is emitted and no default is injected anywhere** — scaffold and TUI included. The provider default or the model route's own encoding (`slng/deepgram/nova:3-en`) applies. Old files with a top-level `language:` fail strict decode with file:line (V3).
- V34 (added 2026-07-20, N17): the ElevenLabs target is gone — `elevenlabs` is not a `Provider` value, a `targets.yaml` naming it fails loudly, no `unmute apply` command exists, the capability matrices carry no elevenlabs rows, and the retired `region`/`edition` instance fields fail strict decode (V3). `elevenlabs` the **model vendor** stays a catalogue entry inside the Pipecat and LiveKit drivers — V20/V21 guard that breadth; deleting those entries is the B4 failure mode, not part of N17.
- V35 (added 2026-07-20, N18): `Target.DeploymentRegion` is an optional free-form string, forwarded as declared and never validated or enum-checked (provider region lists drift; the provider's own CLI fails a typo fast, before anything irreversible exists). Only the pipecat and livekit drivers consume it (pcc-deploy.toml `region` key; README `lk agent create --region`); an unset value emits nothing — no default region is invented.
- V36 (added 2026-08-07, N20): the four generation params `ir.foldParams` writes (`temperature`, `top_p`, `top_k`, `speed`, listed once as `target.GenerationParams`) lower through per-entry `CallSpec` slots. `Catalog.LowerParams` is the single rulebook — `ir.Validate` calls it per binding and `resolveService` calls it for the value it emits — so a param with no slot fails validate rather than emitting a kwarg the constructor rejects at runtime, and a slot renames it to the vendor's own spelling (rime `speed_alpha` on LiveKit, `speedAlpha` on Pipecat, sarvam `pace`, inworld `speaking_rate`). The gate applies **only** to keys the compiler folded from the typed fields: `ir.Binding.Generation` carries that provenance, because once folded a typed `speed` and an author's `params: {speed: ...}` are indistinguishable by name, and the latter must stay forwarded verbatim and unrenamed (D2/D10). Two spellings of one knob (typed `speed` plus `params: {speed_alpha: ...}`) is an error naming both, deliberately unlike the `params.language` override (V33), where the author writes the same word and can see it. Errors carry a binding label ("speak.host") because `add()` dedupes identical strings. The report shows the lowered names, so it cannot contradict the emitted Python (6.2 rule 6). Guards, in both directions: `TestFoldParamsWritesGenerationParams` fails if `foldParams` writes a key `target.GenerationParams` does not list, `TestLowerParamsCoversEveryGenerationParam` fails if that list names one no `CallSpec` field backs, `TestCatalogInvariants` rejects a slot colliding with the entry's model/voice/language/endpoint kwarg, `TestGenerationSlotSpellingsDifferPerFramework` pins the per-framework spellings that look like typos, and the catalogue resolution golden prints every declared slot so a change is reviewable. Runtime verification of the ~59 slot names landed 2026-08-08: `TestSmokePipecatV1GenerationSlotsInstantiate` and `TestSmokeLiveKitV1GenerationSlotsInstantiate` (L4) bind every slot-bearing entry into one package per framework, one throwaway agent per probe, and construct them all in a single venv against the real `pipecat-ai` and `livekit-agents` packages, where a wrong kwarg raises `TypeError`. Values come from `Entry.Call.ParamSlots()`, so a slot added to a probed entry is exercised with no test edit. Smoke is still out of the PR gate, so the coverage guard is not: `TestGenerationSlotSmokeCoverage` fails in the normal suite when a slot-bearing entry has neither a probe nor a written exemption.
