# SPEC — LiveKit driver (generate.Artifact case)

Consumes the core: [compiler.md](compiler.md). Schema truth: [SCHEMA.md](../../SCHEMA.md). LiveKit facts: SCHEMA.md conditions ⁰ + ORCHESTRATOR footnote ⁰. SCHEMA.md wins on disagreement.

Type: **code target**. Emits a LiveKit Agents project on disk (`Artifact.Files`). No generator today. SDK language matters: `sdk_language: python` is required for warm transfer and MCP.

## §G goal
Lower a validated `ir.Agent` + a `livekit` target instance into a runnable LiveKit Agents project: entrypoint (worker/session), agents as `Agent`s with handoff, tasks as `AgentTask`, task groups as `TaskGroup` or a standalone-`AgentTask` sequence, controls, tools, conversation, dependency/deploy files, compile report. The session resolves `listen`/`speak` through the provider catalogue (`internal/target/catalog_livekit.go`): SLNG (`livekit-plugins-slng`) is the scaffold default, and any catalogued per-vendor plugin binds when the user picks it; `reason` lowers to LiveKit Inference, turn detection to Inference, VAD to Silero, optional input noise cancellation to ai-coustics (C8). The `unmute init` example for LiveKit is an invented handoff + task-group agent bound to SLNG, so a first generation is a real SLNG agent, not a random plugin pick (V11, V12).

## §C constraints
- C1: Go emits the project via `text/template` (ADR-0002); embedded FS. Default SDK language `python`; `node` allowed. MCP is Python-only (V9); warm transfer works on **both** languages — stable on Node, Beta on Python (V6). (review-corrected 2026-07-15.)
- C2: all four roles are **open**: every used profile needs a binding (V9 core).
- C3: `TaskGroup` is experimental **and always shares context** → `context_scope: isolated` cannot lower to it; it lowers to a generated sequence of standalone `AgentTask`s instead. `TaskGroup` is itself an `AgentTask`, so on completion LiveKit merges its turns into the owner's context on handoff; `summarize_chat_ctx=True` summarizes them first. Setting `summarize_chat_ctx=False` skips the summarization but NOT the merge (verified against `voice/agent.py` 2026-07-15), so the `merge: results` lowering MUST also snapshot the owner context before awaiting the group and restore it afterward, returning only the typed results (N13). It still passes `summarize_chat_ctx=False` to skip the wasteful summarization call.
- C4: a standalone `AgentTask` starts with an empty chat context and does not propagate its turns back — the typed result is the only return (N13). This is the default (a `preserveFunctionCallHistory` option can override it; the templates must never set it). `reset` history still lands an `AgentHandoff` marker (Node: `AgentHandoffItem`) in the new context.
- C7: version pins are **per-SDK-language** — Python (`livekit-agents`) and Node (`@livekit/agents`) version independently and their namespaces diverge (`beta.workflows` vs stable `workflows`); the template-compatible range is checked per language.
- C5: full turn-detector model is a Cloud/Inference feature with automatic fallback to the mini model → `turn.placement` is a preference; forward + warn, never promise.
- C6: version pins — LiveKit plugins are independently versioned and each needs a `pins:` entry; the driver checks pins against its template-compatible range (codegen check).
- C8 (amended 2026-07-15, catalogue pilot; was "never a per-vendor STT/TTS service"): SLNG is the **scaffold default, not the only route**. `listen`/`speak` resolve through the provider catalogue: `provider: slng` lowers to `slng.STT`/`slng.TTS` from `livekit-plugins-slng`, the bound route as the plugin's `model=` argument with the `slng/` prefix stripped (for example `deepgram/nova:3`, and `deepgram/aura:2` with a `voice`); any other catalogued vendor lowers to its per-vendor plugin (deepgram, elevenlabs, cartesia today, extras on the `livekit-agents` pin); an uncatalogued vendor fails with the matrix diagnostic, never a substitute service. The rest of the recipe is native LiveKit: `reason` to `inference.LLM` (the catalogue's wildcard reason row), turn to `inference.TurnDetector`, VAD to `silero.VAD`, optional input noise cancellation to `ai_coustics`. Reference: the working `taskgroups`/`handoffs` variants at github.com/slng-ai/livekit_orchestration_examples; the SLNG plugin is pinned per C6/T7 (`livekit-plugins-slng`).

## §V invariants
- V1: `task` lowers to a native `AgentTask` (empty context, no turn propagation, typed result only, C4).
- V2: `task_group` with `context_scope: shared` → `TaskGroup` with `summarize_chat_ctx=False` (C3) and an experimental **warning on Python** (stable in Node's `workflows` namespace — no warning there); with `context_scope: isolated` → a generated standalone-`AgentTask` sequence (no TaskGroup).
- V3: `then: return`/`transfer`/`end` all compile; `agent_transfer` is native handoff; `reset` keeps the `AgentHandoff` (Node `AgentHandoffItem`) marker (C4).
- V4: `fallback` lowers natively to `FallbackAdapter` (LLM/STT/TTS) — no generated switcher.
- V5: history `full`/`messages`/`last_n`/`summary`/`reset` all compile (all via `ChatContext` construction); `summary` requires a declared+bound `summarizer` profile.
- V6: `human_transfer` — `mode: cold` native; `mode: warm` native (prebuilt `WarmTransferTask`) on **both** SDK languages — stable on Node (no warning), `beta.workflows` on Python (Beta warning); `briefing: summary` supported (consultation flow: TransferAgent summarizes to the operator); `briefing: message`/`wait` → gated error. (review-corrected 2026-07-15: LiveKit's docs badge lags its shipped code; warm is not Python-only.)
- V7: `requires:` guards are generated machine-checked code (code target); a failed guard returns the model a refusal naming the unmet variables (contract).
- V8: `greeting` — `speaks_first: user`, fixed `text`, model-written opening all generated; `on_voicemail` lowers to `AMD` (leave via `generate_reply` then shut down, or hang up); `placement: local` on listen/speak allowed.
- V9: `mcp` tools compile **only with `sdk_language: python`** → gated error on `node`.
- V10: L4 smoke proves the emitted entrypoint imports/validates; safe_core → livekit emits valid, with the expected `TaskGroup`/turn-placement warnings only.
- V11 (amended 2026-07-15 with C8): every emitted service class travels with its import and install on one catalogue entry (`TestCatalogInvariants`), an unknown vendor fails with the matrix message and never falls through to a substitute service, and slng entries exist for listen+speak (`TestSlngEverywhere`). The Remy golden asserts the scaffold default still emits `slng.STT`/`slng.TTS` + `inference.LLM`; `TestLiveKitV1MultiVendor` asserts per-vendor entries (deepgram/elevenlabs/cartesia) bind with merged `livekit-agents[...]` extras.
- V12: the LiveKit `unmute init` example (`examples/livekit/`) is an invented persona, never the reference Casavo prompt: a greeter that hands off (agent_transfer) to two specialist agents, each running a `TaskGroup` (a journey step, then a shared confirm-contact task). It exercises handoff, task groups, and the SLNG plugin together, and emits valid (V10) with only the permitted `TaskGroup`/turn warnings. The scaffold source package is owned by compiler.md T11; V12 governs only its LiveKit lowering.
- V13 (added 2026-07-16): every `listen`/`speak`/`reason` provider the driver accepts maps to a catalogue entry — import module, `livekit-plugins-<module>` package, api-key env var(s) (or keyless: LiveKit Inference; AWS SDK creds for `aws`), model/voice kwarg names, version floor. No provider silently falls through to a substitute service (the mistake pipecat V11/§B B1 guards). Guarded by `TestLiveKitPluginCatalogCoverage`, mirroring pipecat's `TestServiceInfoCoversEveryMappedClass`; a provider absent from every catalogue and not `slng`/Inference fails loud at generate.
- V14 (added 2026-07-16): validate/generate parity — a spec that validates green for a livekit target must generate (SCHEMA §1 fail-before-generate; PROVIDER_CATALOG F9 one-rulebook). A not-yet-emitted feature gates in the capability table (as pipecat C9 does), never only in a generate-time guard. End state of driver v1: `livekitGuards` and every inline "not emitted yet" refusal are deleted. Guarded by a parity fixture that exercises every SCHEMA §7 livekit-ok feature and must generate clean.
- V15 (added 2026-07-16): the driver consumes every field it validates green — `livekitEmittedFields` agreement test mirrors pipecat's (`pipecatEmittedFields` + its T12 test), so a green-but-ignored field fails a test instead of silently dropping (B1: per-task `model:`). Fail loud is D3; silent drop is the one forbidden outcome.
- V16 (added 2026-07-16): conversation shaping lowers natively — `thinking_audio: subtle` → `BackgroundAudioPlayer(thinking_sound=...)` (`BuiltinAudioClip` preset; verified against livekit-agents source 2026-07-16), `none` → no player; `interruption.minimum_words` → session `InterruptionOptions.min_words` (verified same day: `voice/turn.py`); `ignore_phrases` generated; inactivity/max_duration range-checked per the core warn rows.
