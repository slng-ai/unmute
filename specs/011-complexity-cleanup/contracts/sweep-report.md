# Contract: L5 Example Sweep

**Date**: 2026-08-15 | **Plan**: [../plan.md](../plan.md)

The tool's own contracts — the four commands and the authoring schema — are
unchanged by this feature, and SC-007 requires that. The only new interface is
the acceptance harness, specified here.

---

## Invocation

```text
go test -tags sweep ./internal/cli/... -run TestExampleSweep -timeout 90m
```

**Preconditions**, all checked before the first container builds:

| Precondition | Absent → |
|---|---|
| Docker daemon reachable | Blocked |
| Playwright Chromium available | Blocked |
| Every required secret name present in root `.env` | **Failed**, not Blocked |
| Working directory is the repository root | Failed |

The secret rule differs from the tooling rules on purpose. Missing tooling says
nothing about the code under test, so it blocks. A missing secret means the
sweep cannot deliver the coverage it claims, and FR-035 forbids reporting that
as anything but a failure.

**Selecting a subset** — standard Go test filtering, no custom flags:

```text
go test -tags sweep ./internal/cli/... -run 'TestExampleSweep/salon-support/livekit'
```

## Output

Go subtests, one level per dimension, so `go test -v` reads as the report and
FR-034 needs no extra machinery:

```text
=== RUN   TestExampleSweep
=== RUN   TestExampleSweep/preflight
--- PASS: TestExampleSweep/preflight (0.04s)
=== RUN   TestExampleSweep/simple-prompt
=== RUN   TestExampleSweep/simple-prompt/livekit
--- PASS: TestExampleSweep/simple-prompt/livekit (41.2s)
=== RUN   TestExampleSweep/simple-prompt/pipecat
--- PASS: TestExampleSweep/simple-prompt/pipecat (38.7s)
...
--- PASS: TestExampleSweep (521.9s)
```

**Required in a failure message**, in this order: the example and target, which
stage failed (compile, compose up, page connect, audio wait), the observed
symptom, and the log tail. A bare `session did not start` costs the reader the
whole debug.

```text
--- FAIL: TestExampleSweep/mcp-example/pipecat (62.1s)
    example_sweep_test.go:118: mcp-example/pipecat: no inbound audio within 45s
        stage:    audio-wait
        session:  established (webrtc-offer accepted)
        agent:    container ready, greeting not observed in logs
        logs:     <last 40 lines>
```

## Report artifact

Written to `sweep-<story>-<sha>.json` in the scratch directory, never in the
repository.

```json
{
  "story": "P2",
  "commit": "1085102",
  "ruffVersion": "0.14.2",
  "byteDiff": "clean",
  "verdict": "green",
  "sessions": [
    {"example": "simple-prompt", "target": "livekit", "outcome": "passed", "seconds": 41.2},
    {"example": "simple-prompt", "target": "pipecat", "outcome": "passed", "seconds": 38.7}
  ],
  "missingSecrets": []
}
```

**Rules**:

- `missingSecrets` holds **names only**. No field anywhere in this artifact may
  contain a secret value (FR-036).
- `verdict` is derived, never written directly: `green` requires all thirteen
  sessions `passed` and `byteDiff` `clean`.
- `ruffVersion` is recorded because a byte comparison across two different
  versions is meaningless (R3), and the artifact should be enough to tell later
  whether a comparison was valid.

## Browser driver contract

`internal/testdata/sweep/greeting-probe.js`, invoked by the Go test.

**Input** — argv: the page URL and a timeout in seconds.

**Chromium flags**, fixed: `--use-fake-device-for-media-stream`,
`--use-fake-ui-for-media-stream`, `--autoplay-policy=no-user-gesture-required`.
Together these remove the microphone permission prompt, the real capture device,
and the gesture requirement, which is what lets sixty-five sessions run
unattended.

**Success**: an inbound audio track reports `bytesReceived > 0` from
`RTCPeerConnection.getStats()` before the timeout.

**Output**, one JSON line on stdout; exit 0 on success, 1 otherwise:

```json
{"ok": true, "bytesReceived": 18432, "msToFirstAudio": 2870}
```

```json
{"ok": false, "reason": "no-inbound-audio", "connectionState": "connected"}
```

**Constraints**:

- The driver loads the page as shipped and must not modify it. The tool is under
  test; a page changed to make itself testable would prove nothing.
- No target branch. Pipecat and LiveKit both arrive as WebRTC inbound audio, so
  one probe covers both — the same reason the shipped page has one adapter.

---

## What this contract does not cover

- **The first user turn.** The probe stops at the greeting. Accepted by FR-030b,
  covered by byte-identical output.
- **Telephony routes.** Compile-only under FR-031. The SIP admin token, the
  dispatch token, and the Twirp client stay covered by their existing unit
  tests, which recompute the HS256 signature against the secret with a fixed
  clock.
- **Transcript quality.** That audio arrived is the criterion. What was said is
  not, and cannot change while generated bytes are identical.
