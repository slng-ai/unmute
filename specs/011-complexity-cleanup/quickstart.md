# Quickstart: Validating Complexity Cleanup

**Date**: 2026-08-15 | **Plan**: [plan.md](./plan.md)

How to prove this feature did what it promised: removed roughly 310 lines of Go
plus a 64-line script, and changed nothing. Run from the repository root.

---

## Prerequisites

| Need | Why | Check |
|---|---|---|
| Go 1.24 | Pinned in `go.mod` | `go version` |
| Docker daemon | Browser dev mode runs the deployable image | `docker info` |
| Playwright Chromium | Drives the real page unattended | `npx playwright --version` |
| `ruff`, one fixed version | Formats emitted Python; version affects bytes | `ruff --version` |
| Root `.env`, complete | Real secrets for all seven runnable examples | see below |

**`ruff` matters more than it looks.** Emitted Python is formatted only when
`ruff` is on `PATH`, and different versions format differently. Capture the
baseline and every later comparison with the same version, or with none at all.
Mixing them makes every file look changed and hides a real regression.

**Known gap**: `FIRECRAWL_MCP_URL` is declared by `mcp-example` and is not in the
root `.env`. Supply it before the first sweep. Under FR-035 its absence fails
both of that example's sessions rather than skipping them.

## Step 1 — Record the baseline, before touching any code

```text
git rev-parse --short HEAD          # note this; it goes in every report
ruff --version                      # note this too
go test ./...                       # must be green before you start
```

Compile all eleven examples into a baseline tree kept **outside** the repository
(the scratch directory, not `build/`). Both are prerequisites for FR-001: with no
baseline there is nothing to compare against, and a baseline captured after the
first edit proves nothing.

Then take a **baseline sweep**, before any cleanup:

```text
go test -tags sweep ./internal/cli/... -run TestExampleSweep -timeout 90m
```

This must be Green. A failure here is a pre-existing problem, and finding it now
is the difference between a known-bad starting point and a day spent blaming the
refactor for it.

---

## Step 2 — After each story

Five stories, so five times. Each in order.

```text
make fmt && make lint && make build && make test
```

The gate must be green at every committed step, not only at the end (FR-003).

```text
# Recompile all examples and compare against the baseline tree.
# Exclude .env and livekit*.toml: preservedPatterns restores them on purpose.
```

**A single differing byte is a failure.** The response is to fix the code, never
to regenerate a golden and never to update the baseline (FR-002).

```text
go test -tags sweep ./internal/cli/... -run TestExampleSweep -timeout 90m
```

Thirteen sessions, all Passed, byte diff Clean. Anything else and the story does
not land.

**Sweeps two through five are much faster than the first.** Generated bytes are
identical by FR-001, so the Docker build context is unchanged and every image
layer is cached. Only the `unmute` binary differs between sweeps — which is the
whole point, since every finding in scope lives in the tool, not its output.

## Step 3 — Confirm the cleanup actually happened

```text
go run golang.org/x/tools/cmd/deadcode@latest -test ./...
```

Expect **zero unreachable functions**. It reports two today
(`internal/style/style.go:72` and `:75`), and closing that to nothing is SC-002.

```text
find internal main.go -name "*.go" -not -name "*_test.go" | xargs wc -l | tail -1
```

Expect at least 300 lines fewer than the starting 20,901 if User Story 5 shipped,
or at least 150 fewer if it was dropped (SC-003). User Story 5 is roughly half
the total reduction on its own, which is why the criterion carries two figures.
The deleted `preflight.sh` is a shell script and does not count toward either.

```text
git diff --stat <baseline-sha> -- docs/ docs-site/ examples/
```

Expect **no output**. SC-007 says this work stayed internal, and an empty diff is
what proves it.

```text
go mod tidy && git diff --exit-code go.mod go.sum
```

Expect no change. No dependency was added or removed.

## Step 4 — Run one thing by hand

Automation checks that audio arrived. It does not check that the agent sounds
right. Once, at the end, open one example yourself:

```text
go run . dev examples/simple-prompt --target livekit
```

Speak to it. This is the one thing the greeting probe deliberately does not
cover (FR-030b), and it costs two minutes.

## Reading a failure

| Symptom | Likely cause | First move |
|---|---|---|
| Every file differs in the byte diff | `ruff` version drifted | Compare `ruff --version` against the baseline's |
| One session blocked | Docker or Playwright missing | Blocked is not Passed; fix tooling and re-run |
| `mcp-example` fails both targets | `FIRECRAWL_MCP_URL` still absent | Supply it; see Prerequisites |
| `salon-support` greeting malformed | `--var customer_name` not seeded | Check the harness var table (R5) |
| Session connects, no audio | Agent never spoke | Read the container log tail in the failure message |
| One story's sweep red, previous green | That story caused it | Revert it alone; stories are independent (SC-006) |

The last row is the reason for the per-story cadence. A regression names the
story that introduced it, with no bisecting.

---

## Definition of done

- [ ] Five Green sweeps, one per story, sixty-five sessions passed
- [ ] Byte diff clean on every comparison; zero goldens regenerated
- [ ] Reachability reports zero unreachable functions
- [ ] Non-test Go down at least 300 lines with User Story 5, or 150 without it
- [ ] One story reverted alone and the gate stayed green, proving independence
- [ ] `docs/`, `docs-site/`, `examples/` untouched; `go.mod` unchanged
- [ ] One manual spoken conversation, by a person, once
