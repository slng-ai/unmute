## The pre-existing bug the sweep found

`unmute dev <example> --target pipecat` cannot start any example that emits a
`tools/` package. The container dies on startup:

```text
File "/app/bot.py", line 18, in <module>
    import tools.book_appointment
ModuleNotFoundError: No module named 'tools'
```

The emitted Pipecat `Dockerfile` copies named files —

```text
COPY bot.py ./
{{if .Tracing}}COPY tracing.py ./{{end}}
```

— and never copies `tools/`, while `bot.py` imports from it. The LiveKit
Dockerfile uses `COPY --chown=appuser:appuser . .` and so is unaffected, which
is why exactly the pipecat half of five examples fails:

`multi-task`, `salon-support`, `simple-prompt`, `subagents`, `task-groups`.

`mcp-example` and `pipecat-human-transfer-daily` pass on pipecat because neither
emits a `tools/` directory.

**Not fixed here, deliberately.** It is a correctness bug in generated output,
and this feature's first requirement is that generated bytes do not move
(FR-001). Fixing it changes `internal/generate/templates/pipecat_v1/Dockerfile.tmpl`
and therefore every pipecat golden. It belongs in its own change, with its own
golden update. **It should be filed and fixed next** — it means no Pipecat agent
with package tools can run locally or deploy.

## Where the line estimate was wrong

SC-003 asks for at least 150 lines without US5. The four shipped stories deliver
**84**.

The audit counted lines *removed* and not the lines the replacement *adds*. Two
findings turned out to be close to line-neutral or worse:

- **The primitive type table.** Four `switch` statements (≈44 lines) became one
  table plus three accessors and a fallback row (≈55 lines). It is a **net
  increase of about ten lines** — and still worth doing, because the key set is
  now written once instead of five times. That is the actual win; it was never a
  line-count win.
- **`removeName` → `slices.DeleteFunc`.** Nine call sites each grew a closure,
  giving back most of the eight lines the helper's deletion saved.

The rest behaved as expected: `signJWT` −16, `callService` −13, `checkVersion`
−12, `isTTY` −10, `cmp.Or` −16, `lessLiveKitVersion` −8, `sortedKeys` −6.

**The reduction is real but modest, and the deduplication is the deliverable.**
Deleting a second copy and calling a shared function is often line-neutral; what
changes is that a fix can no longer land in one copy and miss the other.

Separately, `preflight.sh` (64 lines) is deleted. It is shell, not Go, and never
counted toward SC-003.

## Why User Story 5 was dropped

The spec marks it droppable — "highest risk, and SC-003 is met without it. Drop
rather than rush" — and the plan's risk table says the same. It was attempted and
measured before being dropped, not skipped.

The five console list screens share about ten lines each: build one option per
saved item, add "Add …", add "← Back", select, dispatch on the row prefix. Fifty
lines in total.

A generic `listScreen[T]` covering them needs a title, a description, an add
label, a row prefix, the items, a label function, a key function, a details
handler, and (for `editAgents`) extra rows and a second dispatch branch. That is
roughly **40 lines of helper plus 8 lines of struct literal at each of five call
sites — about 80 lines to replace 50.**

Building an abstraction that costs thirty lines more than the duplication it
removes would fail this feature's own test. The five screens stay as they are.

If the goal is revisited later, the honest target is narrower: the option
*ordering* (items, then Add, then Back) is a real invariant worth stating once.
The create flow is not — it differs in zero values, validation, and append target
at every screen.
