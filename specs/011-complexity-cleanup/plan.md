# Implementation Plan: Complexity Cleanup

**Branch**: `011-complexity-cleanup` | **Date**: 2026-08-15 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/011-complexity-cleanup/spec.md`

## Summary

Remove sixteen audited pieces of over-engineering — unreachable code, duplicated
behaviors, hand-written standard-library equivalents, and parameters with a
single value — across five independently revertible stories, changing no
behavior at all.

The technical approach has two halves. The **cleanup** half is ordinary
mechanical Go editing, ordered so each story stands alone. The **verification**
half is the part that needs designing, because the existing test layers cannot
prove what this feature promises: goldens pin generated bytes, but most of the
code in scope produces no generated bytes. It lives in the command layer, where
its only proof is running.

So this plan adds one new opt-in test layer, L5, that compiles the seven
credential-free examples and drives each one through browser dev mode until the
agent speaks. It follows the existing L4 smoke pattern exactly: a build tag, out
of the default suite, skipping when its tooling is absent. It is a test, not a
new command, so the tool grows no user-facing surface.

## Technical Context

**Language/Version**: Go 1.24 (pinned in `go.mod`), `CGO_ENABLED=0` static build.
Standard-library APIs are capped at the `go` directive and enforced by the
`stdversion` analyzer in `go vet`.

**Primary Dependencies**: Unchanged. `spf13/cobra`, `goccy/go-yaml`,
`google/jsonschema-go`, and the Charm stack. **This feature adds no direct or
indirect dependency**; every replacement is standard library or existing code.

**Storage**: N/A. Artifacts are files under `build/<target>/`.

**Testing**: Existing L1 unit, L2 in-process command, L3 golden, L4 smoke
(`-tags smoke`, needs `uv`). This feature adds **L5 example sweep**
(`-tags sweep`, needs Docker, Chromium via Playwright, and a complete `.env`).

**Target Platform**: macOS and Linux developer machines. L5 additionally needs a
working Docker daemon.

**Project Type**: CLI compiler with an interactive console.

**Performance Goals**: None for the tool. The sweep has a wall-clock budget:
thirteen sessions per sweep, five sweeps. Container images are only rebuilt when
generated output changes, and FR-001 guarantees it never does, so sweeps two
through five reuse the layer cache from sweep one.

**Constraints**:
- Generated bytes byte-identical; zero goldens regenerated (FR-001, FR-002).
- Full gate green at every committed step, not only at the end (FR-003).
- No new dependency (constitution, Dependencies).
- Byte-comparison requires a fixed `ruff` version on both sides; see research.md.

**Scale/Scope**: Sixteen findings across fourteen files in four packages
(`cli`, `generate`, `style`, `tui`), plus one root script deleted and two new
test files. Roughly 310 lines of maintained non-test Go removed from a base of
20,901 — about 160 of them in User Story 5 alone — plus the 64-line script,
which is not Go. Five stories, thirteen sessions each.

The audit that opened this feature reported roughly 735 lines. That figure
included the three findings the constitution refuses (spec Out Of Scope), which
account for about 360 lines between them. Only the sixteen findings in scope are
counted here.

## Implementation Order

Stories land in priority order. Each is a separate commit, each leaves the gate
green (FR-003), and each is followed by a full sweep (FR-033).

| Story | Scope | Files | Risk |
|---|---|---|---|
| Pre-work | Record the byte baseline; build the L5 harness; supply `FIRECRAWL_MCP_URL` | new test + driver | Blocks everything; must land first |
| US1 (P1) | Two unreachable helpers, `tui.Run`, `preflight.sh` | 3 | None — nothing can call them |
| US2 (P2) | Seven duplicated behaviors collapse | 7 | Medium — touches live token and Twirp paths |
| US3 (P3) | Five standard-library swaps | 4 | Low |
| US4 (P4) | Two params, one wrapper, one type | 3 | Low |
| US5 (P5) | Five console list screens share one flow | 1 | Highest; droppable, and SC-003 carries a separate lower bar for that case |

Pre-work is not a user story because it delivers no cleanup. It exists because
FR-033 requires a sweep after story one, which requires the harness to already
work, and because FR-001 requires a baseline recorded before the first edit.

## Constitution Re-check (post-design)

Re-run after Phase 1 against what the design actually introduced, rather than
what was proposed.

| Concern raised by the design | Verdict |
|---|---|
| L5 adds a test layer. Does it breach the gate rules? | **PASS.** Build-tagged `sweep`, out of the default suite and the PR gate, blocking rather than failing when tooling is absent — the same shape as L4 with `uv`. FR-032 restates it. |
| The browser driver is a JavaScript file. Does that breach "maintained runtime code MUST be Go"? | **PASS, with the reason stated.** It is test tooling, not runtime code, and the rule it might have breached names Python packages specifically. Governance still requires a stated reason for new surface; research.md R2 is that reason, including the four alternatives rejected. |
| Playwright and Chromium. Is that a new dependency? | **PASS.** Invoked by `exec`, like `ruff`, `docker`, and `uv`. `go.mod` is unchanged, and quickstart.md checks that with `go mod tidy && git diff --exit-code`. |
| The sweep reads a secrets file. Does anything leak? | **PASS.** Names only, everywhere: the pre-check compares presence, and the report's `missingSecrets` holds names. FR-036 and the contract both state it. |
| Blocked sessions could be read as passing. | **PASS, by explicit design.** The data model forbids collapsing Blocked into Passed, and `verdict` is derived so a blocked sweep reports `incomplete`, never `green`. This was the one risk carried out of the pre-design check, and it is now closed. |
| Does the plan change any authoring surface? | **PASS.** No schema amendment, no capability row, no scaffold change. SC-007 asserts `docs/`, `docs-site/`, and `examples/` are untouched, and quickstart.md verifies it with an empty `git diff --stat`. |

**Result: PASS.** No violation, no justification needed, Complexity Tracking
stays empty.
