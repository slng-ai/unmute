# Product

## Register

brand

## Users

Developers who are new to Unmute and want to build, test, and deploy a voice
agent without first learning this repository. They need a clear path from a
small declarative package to a working Pipecat or LiveKit Agents project.

## Product Purpose

Unmute compiles one portable voice-agent specification into target-native
projects that users own. The documentation should make the system easy to
understand, make the next useful action obvious, and state runtime differences
without hiding them.

## Brand Personality

Precise, calm, and practical. The writing uses plain language, short sentences,
and direct examples. The design should feel polished and confident without
becoming decorative or loud.

## Anti-references

Do not make the documentation look like a glossy AI landing page, a dense API
catalog, or a flat list that hides relationships between concepts. Avoid visual
noise, ornamental motion, repeated card grids, and navigation labels that make
one topic appear unrelated to its parent.

## Design Principles

1. Organize around the reader's task, not the repository layout.
2. Show relationships in the navigation and in the page hierarchy.
3. Use one clear title and a small number of descriptive sections per page.
4. Prefer working examples and honest target differences over broad claims.
5. Make the next useful page easy to find.

## Accessibility & Inclusion

Keep navigation usable by keyboard, maintain readable contrast in both themes,
give media useful alternatives, respect reduced-motion preferences, and keep
the Mintlify accessibility check green.
