Every release of the Unmute CLI, newest first. Each entry is that release's
notes as published, and it links to the release on GitHub, where the binaries,
the checksums and the full commit list live.

An entry describes the release it shipped with, not how Unmute behaves today.
The guide is the current answer. Where an entry mentions the Context Router, the
[Context Router page](/optimization/context-router) is the page that explains
how the router decides which turns to treat as repeatable, and which upstream
kinds were validated live here.

<Update label="October 2026" description="v0.9.1" tags={["CLI"]}>

SLNG's own US East is us-east again.

SLNG's agents API renamed its own US East region from us-east-slng to
us-east. This release follows that rename. It only changes packages
with an SLNG target.

Highlights:

* An SLNG target's deployment_region takes us-east for SLNG's own
  US East. SLNG's own region names are now spelled the same as the
  world parts that speech and the router use.
* A retired region name now fails `unmute validate` with the name to
  use and whose region it is. For example:
  slng target deployment region "us-east-slng" was renamed: use
  "us-east" (SLNG's own US East)
  LiveKit Cloud's eu-central and ap-south still point to
  eu-central-livekit and ap-south-livekit.
* The docs, the README and the bundled skill use the new names.

Changes that can break you:

* us-east-slng is refused. Write us-east.
* us-east now means SLNG's own US East. A package that still says
  us-east for LiveKit Cloud now deploys to SLNG's cluster, and
  `unmute validate` does not warn about it. Write us-east-livekit to
  stay on LiveKit Cloud.

How to upgrade:

1. Upgrade unmute: `brew upgrade --cask slng-ai/tap/unmute`.
2. In targets.yaml, change us-east-slng to us-east. Check that any
   us-east you kept for LiveKit Cloud now says us-east-livekit.
3. Run `unmute skill install` to refresh the bundled skill.
4. Run `unmute validate`, then compile again and redeploy.

[Full notes and downloads](https://github.com/slng-ai/unmute/releases/tag/v0.9.1)

</Update>

<Update label="October 2026" description="v0.9.0" tags={["CLI"]}>

One agent.yaml contract, simpler to write.

agent.yaml has one contract now, and no version: line. Tool behaviour
sits next to the tool, handoffs, transfers and flows sit inside the
agent that uses them, and several keys have shorter names. Every old
agent.yaml needs a rewrite, once. A new skill does it for you: read
"How to upgrade".

Highlights:

* One contract. The version: key is gone, and version 1 is gone from
  every target. A file that still has version: is refused at line 1
  with a pointer to the migration guide.
* A migration skill. `unmute skill install` adds `unmute-migrate`. Ask
  your coding assistant to migrate the package, and it runs
  `unmute validate` until the package is clean. The same table is at
  https://unmute.ai/reference/migrate
* Tool behaviour in agent.yaml. A tool's entry says what each result
  saves and says, as `outcomes:` with `if:`, `save:`, `say:` and
  `then: done` or `then: failed`. A step's `start:` says a line, waits
  for the caller, or calls a tool in code as the step opens.
* Lines read the tool directly. A `confirm:` line reads
  `{{input.x}}`, and an outcome's `say:` reads `{{result.x}}`. You no
  longer save a value only to say it.
* Each agent speaks in its own voice. Before this release, every agent
  after a handoff spoke with the first agent's voice. An agent can also
  name its own `listen:` model.
* A handoff's `say:` takes several lines. One is picked each time,
  never the one said last, in the next agent's voice.
* unmute-core 0.18.1.

Changes that can break you:

* `version:` is refused. Delete the line.
* `agents:` is a list: `- name: concierge`, then its keys.
  `instructions:` is `prompt:`.
* `handoffs:`, `escalations:` and `task_groups:` move inside the agent
  that uses them, as `handoffs:`, `transfers:` and `flows:`. A transfer
  names the environment variable with the number, `to: MANAGER_PHONE`,
  and `brief:` makes it warm. `destinations:` is gone.
* A step's `finish:`, `replies:` and `assign:` become the step's
  `tools:` entries with `outcomes:`, and the step's `save:`.
  `opening:`, `announce:` and `opens_with:` become `start:`.
* In a tool file, `assign:`, `replies:`, `announce:`, `announce_wait:`
  and `hidden:` move to the tool's entry in agent.yaml. `inject:` is
  `with:` and reads `state.x`.
* Renamed: prefetch `call:`, `with:`, `save:`; handoff `say:` (a list)
  and `save:`; flow `fills:`; greeting `say:`.
* `mode:`, a task's `inputs:` and `via:` are gone.
* `channels:` and `capacity:` move to the top of targets.yaml.
  `channels:` is a list: `- name: web`.
* The top-level `tools:` list keeps only entries with behaviour. Every
  file in tools/ is a tool already.

Each retired key's error names its new spelling, with the file and the
line.

How to upgrade:

1. Upgrade unmute: `brew upgrade --cask slng-ai/tap/unmute`.
2. Run `unmute skill install` in your project.
3. Ask your coding assistant to migrate each package, or follow
   https://unmute.ai/reference/migrate by hand.
4. Run `unmute validate`, then compile again and redeploy. LiveKit and
   Pipecat projects now pin unmute-core 0.18.1.

Known limits:

* Twilio and SLNG refuse an agent's own `listen:`. They use the
  package's listen model.
* `unmute maintain` does not open a package where an agent has its own
  `listen:` yet.

[Full notes and downloads](https://github.com/slng-ai/unmute/releases/tag/v0.9.0)

</Update>

<Update label="October 2026" description="v0.8.0" tags={["CLI"]}>

Agent.yaml version 2 on every target, built on unmute-core.

LiveKit and Pipecat agents now compile onto unmute-core, the library
that holds the voice-agent behaviour both frameworks share. The model
picks what to do. Code says the lines that must be exact: read-backs,
offers and receipts. Version 1 packages no longer compile for LiveKit
or Pipecat, so read "Changes that can break you" before you upgrade.

Highlights:

* agent.yaml version 2. Your call state is a Pydantic `State` class in
  `state.py`. A local tool takes its types from its Python handler:
  `local: handler: tools/salon.py:find_slots`. New keys let code do the
  exact parts: a tool's `assign`, `replies`, `precheck` and
  `announce_wait`, and a task's `finish` rule with `confirm` and `say`.
* Fewer model requests. The salon example books with one model request
  per caller turn. On version 1 it took two or three.
* Every target reads version 2. Twilio and SLNG keep their own
  runtimes. On SLNG, `unmute deploy` publishes your typed Python tools
  as SLNG code tools, and a `finish` rule can end a step on one tool.
* New runtimes: LiveKit Agents 1.8.8, Pipecat 1.12.0, Python 3.12, and
  unmute-core 0.17.1.
* `unmute dev` runs version 2 projects. The dev page now shows how long
  the caller waited on tool turns too.
* The docs site has a second tab, Unmute Core, with the library's docs.

Changes that can break you:

* LiveKit and Pipecat compile version 2 only. A version 1 package now
  fails `unmute validate` with:
  "livekit compiles agent.yaml version 2 only: set `version: 2`, add a
  state.py and type your local tools". Twilio and SLNG still accept
  version 1.
* `targets.yaml` must pin LiveKit "1.8.8" and Pipecat "1.12.0". Any
  other version is refused.
* Not compiled yet on LiveKit and Pipecat: `mcp:` and `slng:` tools,
  builtins other than `end_call`, and `tracing: coval`. Langfuse
  tracing works. The tools still work on the slng target.
* The build folder is new. It holds `agent.json`, `spec.py`,
  `speech.py`, `agent.py` or `bot.py`, `compose.dev.yaml` and a
  `Dockerfile`. `call.py`, `settings.py`, `prompts/`, `utils/`,
  `pcc-deploy.toml` and `sip-*.json` are gone. Pipecat Cloud now takes
  its agent name, secrets, region and `--min-agents` as
  `pipecat cloud deploy` flags. You write LiveKit SIP trunk and
  dispatch files yourself.
* `warm_instances` and `deployment_region` have no effect on a LiveKit
  or Pipecat build yet.
* `compile-report.json` lists only the target, the runtime and the
  required environment variables.
* LiveKit Speechmatics 1.8.2 ignores ten settings without a word. The
  compiler now refuses them.
* `unmute dev` no longer forwards a Coval simulation header. Coval is
  still a tracing target on version 1 and on the slng target.

How to upgrade:

1. Upgrade unmute: `brew upgrade --cask slng-ai/tap/unmute`.
2. For each LiveKit or Pipecat package, set `version: 2`, add a
   `state.py` with `class State(BaseModel)`, and point each local tool
   at a typed handler. Then run `unmute validate`. It names each key to
   change. Guide: https://unmute.ai/reference/agent-yaml-v2
3. Move the target versions in `targets.yaml` to "1.8.8" and "1.12.0".
4. Compile again and redeploy. Update any deploy script that reads the
   old build files.
5. Run `unmute skill install` to refresh the bundled assistant guidance.

Known limits:

* On the dev page, Pipecat realtime and live models ignore typed
  lines. Voice works.
* On LiveKit, GPT-Live does not hand a typed line to its backend
  model, so the backend's tools do not run. Spoken turns are not
  tested yet.
* A step's receipt, like "Lovely, your haircut is booked", shows no
  "Caller waited" on the dev page yet.

[Full notes and downloads](https://github.com/slng-ai/unmute/releases/tag/v0.8.0)

</Update>

<Update label="October 2026" description="v0.7.0" tags={["CLI"]}>

Call state in state.py, and tasks on SLNG managed agents.

How to upgrade:

1. Upgrade voiceai: `brew upgrade slng-ai/tap/voiceai`. Deploying a
   task that lists tools needs voiceai 0.1.20 or later.
2. Upgrade unmute: `brew upgrade --cask slng-ai/tap/unmute`.
3. Install uv (https://docs.astral.sh/uv/) if a package has variables.
   unmute now reads state.py with it. The first run needs network.
4. Run `unmute validate` on each package. Every old form is refused
   with its file, its line and where it moved. The fixes are below.
5. Run `unmute compile` and deploy.

Breaking changes:

* The call state is a Pydantic model in state.py. Why: types,
  defaults and descriptions are now real Python that Pydantic checks,
  not a type grammar inside YAML. How: move each variable's `type:`,
  `default:` and `description:` to a field on `class State(BaseModel)`
  in `<package>/state.py`. `variables:` in agent.yaml is now a list. It
  keeps only the values that need `source:` or `confirm:`.

  ```yaml
  # before, agent.yaml
  variables:
    caller_phone:
      type: Phone
      default: ""
      confirm: verify_contact
      description: The caller's number in E.164.

  # after, agent.yaml
  variables:
    - name: caller_phone
      confirm: verify_contact
  ```

  ```python
  # after, state.py
  class State(BaseModel):
      caller_phone: Phone | None = Field(None, description="The caller's number in E.164.")
  ```

  The old form fails with:
  `variables: is a list now. Types, defaults and descriptions live on State in state.py`.

* `shapes:` is gone. Why: a shape is a type, and types now live in
  state.py. How: write each shape as a `BaseModel` class in state.py
  and use it as a field type on State.

* Templates name a saved value as `{{state.x}}`. Why: the name now says
  where the value lives, a field on State in state.py. How: change
  `{{x}}` to `{{state.x}}` in the greeting, prompts, tool `inject:`,
  webhook `path:` and prefetch `args:`. `{{$NAME}}` is unchanged. The
  old form fails with:
  `{{x}} names a value on State; write {{state.x}}`.

* A step must return every value its `assign:` names. Why: every field
  that starts empty is now `| None`, so `| None` can no longer mean
  "the step may leave this out". How: add `?` to a value the step may
  skip: `- callback_time: result.callback_time?`. Lists (`x+:`) stay
  optional. Nothing fails at validate, so read each `assign:` once.

* Pipecat needs `params.world_part` on SLNG speech. Why: pipecat-slng
  0.6.0 made it required, and a Pipecat bot without it failed at
  start. How: add `world_part: eu-north` (or your region) under
  `params:` on each SLNG `listen` and `speak` binding. `unmute validate`
  refuses a Pipecat package without it. LiveKit is unchanged. The SLNG
  target drops `world_part`, so one package can target Pipecat and SLNG.

New:

* Tasks and task groups on SLNG managed agents. Why: SLNG managed
  agents now run tasks. How: write tasks the same way as for LiveKit
  and Pipecat, and add `slng` to the targets. A tool that only a task
  uses is attached hidden from the main agent. `unmute validate` names
  what SLNG still refuses: a model per task, `finish:` rules,
  `history: summary`, a group ending in anything but `return`, and
  handoffs.

* Typed values on SLNG. A value a task saves, or one the model records
  with `source: conversation`, can be a phone number, email, date,
  time, `Literal`, list or model. A value the dispatch fills stays
  plain text.

* Logfire tracing on LiveKit and Pipecat: `tracing.provider: logfire`
  with `LOGFIRE_TOKEN`. Langfuse and Coval settings are unchanged.
  LiveKit no longer installs the langfuse SDK, and its traces drop the
  empty wrapper rows.

Generated code:

* Generated Python passes its own ruff and ty rules. Each project
  carries them in pyproject.toml.

* Each code target writes a small project instead of one big file:
  settings.py, session.py, agents.py, call.py, utils/, and prompts in
  prompts/*.md. Twilio splits app.py the same way. The entry file
  keeps its name (bot.py, agent.py, app.py), so deploy commands do not
  change. If you edited a generated file by hand, find your edit in
  the new layout.

* The saved call state is a real Pydantic model at runtime. A saved
  model holds a model, not a dict. Call-start values and carrier
  facts now go through the same check as every other save.

- A first-call walkthrough covers Twilio account setup, getting a
  number, compiling locally, publishing the app, and connecting it.
  Hosting examples show container services, a VM, and a laptop tunnel.

- The shipped example was verified on a deployed application with a

Getting started:
  unmute init my-agent --target twilio

<Update label="September 2026" description="v0.6.0" tags={["CLI"]}>

Pipecat steps that start on the caller's words, one trace per call, and prompts checked against replayed calls.

Highlights:

* Pipecat: a task step now opens on an instruction. It speaks its
  opening line first, then gives the model an instruction that points at
  what the caller already said. Before, the request ended on the model's
  own sentence. The model then asked again for details it had, sometimes
  invented a value, and sometimes returned nothing. That last case left
  the caller in silence. Without any instruction, a step acted on a
  request before asking for a yes.

* Pipecat tracing: two calls on one worker stay apart. Per-call state
  lives in a context variable now. A warm worker no longer files one
  call's spans under another call's session.

* LiveKit tracing: one call is one trace again. The event loop monitor
  sent an `event_loop_blocked` span with no parent when the loop stalled
  for more than 100 ms. That span could split a call into two traces.
  It is no longer exported.

* Every Pipecat build answers the Twilio route of the runner. A
  browser-only example can now take a simulated phone call too.

* `{{$NAME}}` in a prompt or greeting now fails `unmute validate` on
  every target. On `slng` it used to pass validation and then fail at
  push, because the backend removed org variables on 2026-09-02. The
  error says where a Vault token still works: an MCP server URL. A tool
  still names its secret by bare name in `auth:`.

* The salon prompts were fixed where replayed calls showed them wrong.
  The agent asks for a number it does not have instead of inventing
  one. It reads back a number given in pieces once, whole. It runs
  verification before it records a complaint, so it never says it saved
  something it did not. It no longer offers a transfer nobody asked for.

For contributors:

* `make sim TEST_SET=<id>` runs one Coval test set against the examples
  running on your laptop, on both LiveKit and Pipecat. It exits 1 when a
  call did not finish, the agent never spoke, or a metric said NO. See
  `utils/coval_sim/README.md`.

* `scripts/text_run_pipecat.py` drives a compiled Pipecat bot through
  scripted caller lines. It uses the real model and the local tools, with
  no audio. It takes the same flags as `text_run_livekit.py`.

Upgrade notes:

* Recompile. The Pipecat bot template and both tracing templates
  changed.

* If a prompt or greeting uses `{{$NAME}}`, move the value into a
  package variable (`{{name}}`) or into the MCP server URL. It was already
  refused at push on `slng`. Now `validate` says so first.

* Run `unmute skill install` again. The skill's package and deploy
  references changed with the Vault token rule.

<Update label="September 2026" description="v0.5.6" tags={["CLI"]}>

Task groups that speak on Pipecat, a booking turn that costs one request less, and a docs tree that stopped rotting.

Highlights:

* Task groups work on Pipecat. A step's opening line was emitted as a
  Flows `tts_say` pre-action, and a pre-action holds the node until the
  frame behind it reaches the worker sink, a frame this worker queues
  does not move until the tool call building the flow returns. The
  first node of every flow waited on itself: nothing spoken, nothing
  asked of the model, the caller left hanging. It is a queued
  `TTSSpeakFrame` now, so nothing waits. `opening: listen` was broken
  the same way and is fixed by the same change. Two runtime smokes
  hold it; both time out on the old template.

* The salon's `book` group is back, and a booking turn spends one model
  request fewer. `manage_booking` loses its `when:`, so the group is
  the only way in, and `skip_when_confirmed:` decides verification
  again. That is the general shape, now written down at

  The dev page gained a logs view fed by server-sent events, and the listener
  now binds before the target starts, so a failed container build is visible
  instead of invisible on exactly the runs whose output you need. Output
  produced before the browser loads is replayed on connect, and Last-EventID

  Each agent turn carries its own timing line: end to end, time to first byte
  per service, and how long the reply took to stream. Every tool the turn
  called gets its own row above the reply it delayed, which is where it

  reporting as a single 51-second tool call. An unreported value renders as a

  Develop and test explains where the time goes in a voice turn, with field

Coval as a first-class tracing integration
  tracing: provider: coval compiles to a project that sends Covals canonical
  spans on both code targets, with no correlation code written by the package
  author. Both of Covals correlation routes are used: a call Coval placed
  exports against the simulation ID on the call, and any other call is
  registered as a Coval conversation when it ends and exports against the
  conversation ID that comes back. That second route is what puts a local
  unmute dev run in Covals Trace Search. Spans are held, capped, and flushed
  once an ID arrives, so nothing before correlation is lost.
  The two targets reach the span tree differently, because the frameworks
  differ. Pipecat already nests its spans the way Coval wants, so they are
  renamed in flight. LiveKits shape cannot be fixed by renaming, since a
  spans parent is fixed when it starts, so the LiveKit module leaves
  LiveKits own OpenTelemetry off and builds Covals tree from session
  events, using only numbers LiveKit measured itself. Each llm span carries
  the prompt that round actually ran on, under the same attribute names on
  both targets. A number that was never measured is left off rather than sent
  as zero.

LiveKit turn latency, measured across three calls per setting
  A session of live latency work on salon-concierge, with every claim taken
  from three calls rather than one, because two calls on an identical build
  differed by 1.1s of mean silence.
  - The transcriber, not any endpointing number, was buying a two-second
    penalty per turn: a turn whose transcription_delay reached 1.0s got the
    2.5s max_delay instead of the 0.58s floor. deepgram/nova:3 finalises in
    0.159s mean against gradiums 0.999s, with the same words in every
    transcript.
  - endpointing_delay now sets the silence window it always claimed to. On
    LiveKit it renders as the prewarmed Silero VADs min_silence_duration
    instead of an endpointing min_delay that could never fire before the VAD
    reported end of speech, so every authored value under 0.55s used to be
    silently inert. Under 250ms is now a compile error, not a first-call
    crash. Unset stays byte-identical and no golden moved.
  - Warm TTS standby stays, with the claim corrected: it is worth about 40ms
    of caller-visible time, not the 610ms first reported, plus a real floor
    improvement from 221ms to 58ms on the best segment. The earlier number
    was the websocket handshake, which was already off the callers path.
  - Control hops came out of the turn. Verification asks for a phone number
    only, booking is one task instead of a three-step group, and finish calls
    in a scripted booking drop from 7 to 2. Tool state moved from SQLite to
    memory, so get_current_date went from 245ms to 7.7us. llm ttfb over ten
    samples: 1.212s to 0.895s. Authored prompt text is down 61%.
  - A delegated task no longer answers its parents in-flight call. LiveKit
    injects the still-running delegate call and a placeholder result into the
    context the task generates from, so the caller heard an apology for a
    failure that had not happened. The strip keys on the SDKs own
    __lk_running_placeholder__ marker. Scripted bookings went from eleven or
    twelve agent turns to seven.
  - announce: is a new optional scalar on a webhook or local tool file: one
    fixed sentence the agent speaks as the tool starts. The wait is not the
    tool, which returns in 1 to 14ms here, it is the second LLM round trip
    and the TTS after it. Works on both code drivers, including tools listed
    on a Pipecat task, which a wrong capability claim had refused.
  - docs-site gained a top-level Optimization group and the skill gained
    references/latency.md, both carrying the seven settings that looked
    promising and were not, with reasons, so nobody repeats that day.

The SLNG Context Router, fully integrated
  provider: slng on the think role puts the Context Router in front of your
  own reasoning model. A repeated turn is answered from cache; a miss goes to
  the upstream you name, so you keep your model, your provider, and the bill
  for turns that reach it. Authoring is agent_id, upstream, and
  params.world_part_override for the regional base URL, over five upstream
  spellings across openai, openai-compat, azure, vertex and bedrock.
  On LiveKit it lowers to extra_headers and extra_body on openai.LLM; on

  salon-concierge is now the one place the binding is demonstrated, and it

<Update label="August 2026" description="v0.1.1" tags={["CLI"]}>

The first release of Unmute, a command line compiler for voice agents.

You write a small package of YAML and Markdown that says who the agent is, which
models it uses, and which tools it can call. Unmute turns that into a real Python
project for the orchestrator you picked. The project it writes is yours: pinned
dependencies, a Dockerfile, a runbook, and no dependency on Unmute at runtime.
Unmute compiles ahead of time and is never in the call path.

**What is in this release**

**Four commands.** `init` scaffolds a package, `validate` checks it against its
targets and names the file and the line when a field is wrong, `compile` writes
one project per target under `build/`, and `dev` compiles, runs the agent locally
and lets you talk to it in the browser. Add `--console` and you talk over the
terminal mic and speaker with no Docker in the way. `validate` prints one status
line per target, and every refusal names the fix.

**Two code targets, one agent.** The same package compiles for Pipecat and for
LiveKit. Nothing in `agent.yaml` mentions either one. Where a runtime cannot run
a model as defined, `targets.yaml` overrides that single entry by name and the
agent itself does not change.

**Models named once.** Every listen, think, speak and turn model is declared once
and referenced by name. Point `brain` at a different model and every agent using
it follows. A provider catalogue turns each binding into code, so the emitted
service carries its own import, its dependency pin and its required environment
variable, and a provider with no slot on a framework fails by name instead of
quietly emitting the wrong class. Pipecat covers anthropic, assemblyai, cartesia,
deepgram, deepseek, elevenlabs, google, gradium, groq, inworld, mistral, openai,
openrouter, qwen, rime, sarvam, slng, soniox and speechmatics. LiveKit covers the
same ground through its native per vendor plugins, plus aws, azure and gemini. An
unknown vendor is still legal as a custom OpenAI compatible endpoint, and
`provider: local` runs the Silero turn detector on your own machine.

**Multi-agent, tasks and task groups.** Any number of agents, with
`agent_transfer` between them and history you control per transfer (full,
messages, last n, summary or reset). Delegates run a single task or a task group
and return where the contract says they return. Task groups can chain, hand over
or end. A task can name its own model, so one stage can be cheaper or stronger
than the rest of the conversation. Both drivers lower all of this to native
primitives: Pipecat Flows on the owning agent, and LiveKit AgentTask sequences
with typed session state.

**Tools, four ways.** A webhook tool with bearer or API key auth. A local Python
handler in `tools/<name>.py`, copied in beside the agent. An MCP server as a tool
source on both code targets, with optional transport and an optional list of the
server tools to offer. And prebuilt tools from the registry, `end_call` in v1,
with an optional closing line. `inject` adds values to a tool call that the model
never sees and cannot overwrite, which is where a user id or a captured slot
rides along.

**Variables and secrets.** Typed input variables, usable in templates, injected
into tool calls and captured back out of the conversation. `secrets` lists every
environment name the author wrote, and the compiler cross checks the secrets your
local handlers actually read. Every `*_env` field is a name and never a value, so
a pasted URL or key fails validation instead of landing in the spec. Seed a
variable for a local session with `unmute dev --var name=value`, the stand in for
a real dispatch payload.

**Telephony.** Real phone calls on the routes each platform ships: LiveKit SIP
with a Twilio trunk, the LiveKit Twilio connector, the Pipecat carrier WebSocket
route, and Pipecat on Daily, either with a Daily number or with your own carrier.
`unmute dev --telephony` runs the resolved route end to end from your laptop:
it brings up the routes Compose graph, opens a managed tunnel, points the Twilio
webhook at it and writes the local LiveKit SIP trunk records, so a first phone
call takes no manual setup. `--to` places an outbound test call, and
`--public-url` or `--no-webhook` hand the carrier callback back to you. Local
runs need no cloud account, only a carrier account and what runs on your machine.

**Human transfer.** Cold and warm handoffs written as `cold:` and `warm:` blocks,
with their parameters in the shape block. Each route uses the platforms own
primitive and the generated code never owns the audio path: SIP REFER on LiveKit
SIP, Dailys room reroute on both Daily number forms, and a carrier markup
replacement on the Pipecat carrier stream. Warm transfer lands on LiveKit SIP,
with your briefing and the transcript going to the person who picks up. Where a
platform has no primitive, `validate` refuses and names the routes that work.
Generated transfer tools log which control fired, and a cold transfer refuses in
words when the session is not a phone call.

**Tracing.** A `tracing` block that lowers to each platforms native
integration, with Langfuse examples on both targets.

**Secrets that match reality.** Compiled output carries a `.env.example` holding
exactly the variables that agent needs, and the generated project checks them at
startup instead of failing mid call.

**A runbook per build.** Each `build/<target>/` gets its own `README.md`,
`Dockerfile`, `compose.dev.yaml`, the platform deploy file, and a
`compile-report.json` recording what was resolved, which catalogue entry produced
each service and when that entry was last checked against upstream docs.

**Examples that run.** `examples/` holds packages that each compile for both
targets: `salon-support` needs nothing but a browser and two keys,
`twilio-telephony-hello` places a real phone call, `multi-task`, `task-groups`
and `subagents` cover staged conversations, `mcp-example` wires an MCP server,
and three transfer examples cover the three mechanisms.

**Getting it**

One static binary for darwin, linux and windows, on amd64 and arm64.

```sh
brew install slng-ai/tap/unmute              # macOS
winget install slng.unmute                   # Windows
go install github.com/slng-ai/unmute@latest  # anywhere with Go 1.24+
```

Archives are on the release page, each holding the binary, the LICENSE and the
README, alongside a signed `checksums.txt` and one SBOM per archive.
`unmute --version` reports its own commit and build date.

MIT licensed.
