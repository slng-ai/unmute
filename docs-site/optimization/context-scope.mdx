Each model request has three inputs: its own instructions, the conversation
allowed at that boundary, and the saved values its prompt names. Unmute keeps
those choices separate.

## Start with `messages`

Omitting `context.history` means `messages`. The receiver keeps caller and
agent speech while tool calls and replies are removed together.

| Need | Choose |
|---|---|
| Normal continuity without old tool records | `messages` |
| Earlier paired tool records too | `full` |
| Only a recent bounded window | `last_n` with `max_messages` |
| No earlier conversation | `reset` |
| A generated summary on LiveKit | `summary` with `summarizer` |

`full` and `reset` both remove earlier instructions. The receiver always uses
its own instructions.

## Declare once, save once, read where needed

```yaml agent.yaml
variables:
  appointment_id:
    type: Id
  appointment_date:
    type: Date
  appointment_time:
    type: Time

agents:
  concierge:
    tasks:
      - name: choose_booking
        instructions: tasks/choose-booking.md
        assign:
          - appointment_id: result.appointment_id
          - appointment_date: result.appointment_date
          - appointment_time: result.appointment_time

      - name: reschedule_booking
        instructions: tasks/reschedule-booking.md
        context:
          history: reset
```

```markdown tasks/reschedule-booking.md
Move appointment {{appointment_id}} to {{appointment_date}}
at {{appointment_time}}.
```

The first task's assignments derive its typed finish arguments from the three
variables. The reset task receives only the three values it names. It receives
no automatic state block, request, summary, or triggering sentence.

If a reset receiver needs a detail that was only spoken and never saved, it
asks the caller again. This is the useful pressure of `reset`: the package must
state which data crosses the boundary.

## Dotted paths stay narrow

`{{appointment.date}}` sends the date field. It does not serialize the whole
appointment. `{{appointment}}` sends the whole value as compact JSON.

An unset value renders as `none recorded yet.` Declaring a description never
fills a value and never sends it to a prompt.

## Tool injection is separate

A tool can read saved values without showing those arguments to the model:

```yaml tools/modify_booking.yaml
input:
  type: object
  properties:
    confirmed:
      type: boolean
  required:
    - confirmed
inject:
  - booking_id: "{{appointment_id}}"
  - date: "{{appointment_date}}"
  - time: "{{appointment_time}}"
```

Injected keys are removed from both the model-visible `properties` and
`required` lists. Exact placeholders keep their native type. Mixed text becomes
text. A missing or unconfirmed injected value stops the tool before execution.

## Confirmation

A variable with `confirm: verify_customer` is a candidate until that named task
saves it. The verifier may reference the candidate in its own prompt. Other
prompts and guarded tool reads see it as unavailable.

When an input changes, values prefetched from the old input are invalidated.
Unrelated values, such as the local date, remain.

## History is not redaction

`messages` keeps earlier speech, including a value the caller said aloud.
Variable scoping controls explicit saved-state sharing. Use `reset` when the
receiver should inherit no transcript.

## Cross-target choices

| Field | LiveKit | Pipecat |
|---|---|---|
| `full`, `messages`, `last_n`, `reset` | supported | supported |
| `summary` | supported | refused |
| `include_tool_calls: false` | supported | refused |
