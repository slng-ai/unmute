`agent.yaml` is the agent. Nothing in it is specific to a runtime; that lives
in [targets.yaml](/reference/targets-yaml).

YAML decoding is strict. An unknown field is an error with the file and the
line, not a shrug.

Durations use Go duration syntax, for example `90s`, `15m`, or `1h30m`.

```yaml agent.yaml
version: 1
entry_agent: greeter

models:
  think:
    reasoning:
      provider: openai
      model: gpt-5.6-terra
  speak:
    voice:
      provider: slng
      model: "slng/deepgram/aura:2-en"
      voice: "aura-2-thalia-en"
  listen:
    transcriber:
      provider: slng
      model: "slng/deepgram/nova:3-en"
  turn:
    detector:
      provider: local
      model: silero

agents:
  greeter:
    instructions: instructions.md
    model: reasoning
    voice: voice

channels:
  web:
    kind: realtime_audio

capacity:
  peak_sessions: 2
  max_sessions: 5
  avg_session_duration: 3m
```

## All keys

| Key | Type | Required | Default | Allowed values | Meaning |
|---|---|---|---|---|---|
| `version` | integer | yes | — | `1` | schema version |
| `entry_agent` | string | yes | — | declared agent name | agent that answers |
| `models` | map | yes | — | sections `think`, `speak`, `listen`, `turn` | model palette grouped by kind |
| `listen` | string | with 2 or more listen chain heads | sole chain head | declared `models.listen` name | listen entry to use |
| `turn` | string | with 2 or more turn entries | sole entry | declared `models.turn` name | turn entry to use |
| `variables` | map | no | — | lower snake case names | per-call values |
| `secrets` | list of strings | no | — | UPPER_SNAKE names | environment values the generated project reads |
| `destinations` | map of strings | when `human_transfer` is used | — | lower snake case names to UPPER_SNAKE env names | phone destinations controls may use |
| `agents` | map | yes | — | one or more lower snake case names | agent prompts, models, and callable names |
| `tasks` | map | no | — | lower snake case names | delegated steps |
| `task_groups` | map | no | — | lower snake case names | ordered task sequences |
| `controls` | map | no | — | lower snake case names | delegates and transfers |
| `tools` | list of strings | no | — | loaded tool file names | tool files to load |
| `conversation` | object | no | — | keys below | greeting, interruption, inactivity, and limits |
| `tracing` | object | no | — | `provider: langfuse` or `provider: coval` | tracing provider |
| `channels` | map | yes | — | one or more channel definitions | how people reach the agent |
| `capacity` | object | for telephony or code targets | — | positive values; constraints below | traffic estimate |

## `models`

Four sections. The section an entry sits in decides its kind: `think` (LLM),
`speak` (TTS), `listen` (STT), `turn` (turn detection). Entry names share one
namespace across sections and are yours to choose.

```yaml
models:
  think:
    reasoning:
      provider: openai
      model: gpt-5.6-terra
      params:
        reasoning_effort: "none"
```

Which fields are legal depends on the section:

| Field | Legal section |
|---|---|
| `provider`, `model`, `endpoint_env`, `placement`, `params`, `description` | `think`, `speak`, `listen`, `turn` |
| `voice`, `speed` | `speak` |
| `language` | `speak`, `listen` |
| `temperature`, `top_p`, `top_k` | `think` |
| `semantic_endpointing` | `turn`: `required`, `preferred`, or `off` |
| `endpointing_delay` | `turn`: a positive duration, how long to wait after speech stops before taking the turn |
| `fallback` | `think`, `listen` |

| Field | Values and constraints |
|---|---|
| `provider` | a provider from the target's model catalogue; `local` also implies local placement |
| `model`, `voice` | provider values, passed through as written |
| `params` | provider values passed through as written, except the LiveKit OpenAI Responses directive described below |
| `speed`, `temperature`, `top_p`, `top_k` | numeric provider values, forwarded as written |
| `language` | BCP-47 tag such as `en` or `en-US` |
| `endpoint_env` | UPPER_SNAKE environment variable name for a custom endpoint |
| `placement` | `api` or `local`; when omitted, `provider: local` means local and another named model means API |
| `fallback` | names in the same section; chains are flattened and cycles are refused |
| `description` | author note |

Entries you do not reference are legal alternates.

The provider catalogue has two wildcard routes. Pipecat accepts an unlisted
listen, speak, or think provider only with `endpoint_env`, through an
OpenAI-compatible integration. LiveKit accepts an unlisted think provider
through LiveKit Inference; its listen and speak provider lists are closed.
Never invent a provider name for either route.

`model` and `voice` are passthrough. Most `params` are too: a name the target's
settings object has no field for rides that target's overflow field and reaches
the provider. The narrow exception is `api: responses` on a LiveKit OpenAI
reasoning binding. Unmute checks that directive, selects the Responses client,
and turns `reasoning_effort` into the API's nested reasoning setting.
[Reasoning model](/models/llm) shows the target-local form and explains why.

Do not guess model ids, voice ids, or params. Use values the user supplied or
values verified in the provider's own documentation.

## `variables`

```yaml
variables:
  customer_name:
    type: string
    source: call_start
    default: there
    description: Caller's first name.
```

| Field | Values |
|---|---|
| `type` | `string`, `number`, `integer`, `boolean` |
| `source` | `call_start`, `conversation`, or a system source |
| `default` | any value of the declared type |
| `description` | a note, also read by the model for `conversation` variables |

Full detail on [variables](/reference/variables).

## `secrets`

```yaml
secrets:
  - OPENAI_API_KEY
  - SLNG_API_KEY
  - SIP_TRUNK_HOSTNAME
  - SIP_AUTH_USERNAME
  - SIP_AUTH_PASSWORD
  - SIP_FROM_NUMBER
  - BILLING_PHONE_NUMBER
  - SUPERVISOR_PHONE_NUMBER
```

A list of UPPER_SNAKE environment variable names. Never values, and never usable
in a `{{template}}`. That list is `examples/livekit-human-transfer`'s: two model
keys, the four names its connection maps, and the two desks it can transfer to.

Declare every environment name the generated project reads: names written in
tool and connection fields, destination values, literal `os.environ` reads in
local handlers, provider API keys inferred from the model catalogue, and the
names your tracing provider needs when tracing is enabled. Names the driver or platform
supplies, such as `REDIS_URL` or `DAILY_API_KEY`, stay out. See
[secrets](/reference/secrets).

## `destinations`

```yaml
destinations:
  billing_line: BILLING_PHONE_NUMBER
  supervisor_line: SUPERVISOR_PHONE_NUMBER
```

The symbols a `human_transfer` control can name. A value is only the UPPER_SNAKE
name of an environment variable holding an E.164 number or a `sip:` URI, read at
call time. A number written here is refused, because `agent.yaml` is the portable
half of a package:

```text
agent.yaml:60: destination "billing_line" is a literal. agent.yaml is
  the portable half of a package, so a destination names an environment variable holding
  the number: billing_line: BILLING_PHONE_NUMBER
```

The model never sees a number, and cannot dial one that is not listed here.

## `agents`

```yaml
agents:
  appointment_desk:
    instructions: instructions.md
    model: reasoning
    voice: voice
    tools:
      - check_availability
```

| Field | What it is |
|---|---|
| `instructions` | path to a Markdown prompt in the package |
| `model` | a `models.think` entry name |
| `voice` | a `models.speak` entry name |
| `tools` | names this agent may call: loaded tool files and controls; definitions never go here |

## `tasks`

```yaml
tasks:
  customer_record:
    instructions: tasks/customer-record.md
    tools:
      - lookup_customer
    result:
      customer_id: string
      record_status:
        enum:
          - existing
          - created
          - failed
    context:
      history: full
```

| Field | What it is |
|---|---|
| `instructions` | the task's own prompt file |
| `tools` | names this task may call: loaded tool files and controls; definitions never go here |
| `model` | optional override of the thinking model |
| `result` | the typed result returned by the whole task, not a tool's `output` schema |
| `context` | what the task sees, see below |

Every task needs a non-empty `result:`. Each result field is one of:

- a primitive name: `string`, `number`, `integer`, or `boolean`,
- an `{enum: [...]}` block with at least one string, or
- a JSON Schema object for a nested shape.

`unserved_request` is reserved and a result declaring it is a validation error.
Every generated task finish already takes it, optional and empty by default, for
a request the step could not serve. See
[tasks](/build/orchestration/tasks).

**Task `result:` and tool `output:` are different contracts.** A task result is
enforced and describes what the calling agent receives after the task finishes.
A tool's optional `output:` is only an author-side description of one call today;
it is not sent to the model, emitted in the compile report, or enforced at run
time.

### `context`

Used by tasks and by transfer controls.

| Field | Values | Notes |
|---|---|---|
| `history` | `full`, `messages`, `last_n`, `summary`, `reset` | required |
| `max_messages` | a positive number | legal with `last_n` only |
| `summarizer` | a model entry name | legal with `summary` only |
| `include_tool_calls` | `true` or `false` | whether tool calls travel too |
| `variables` | `all` or a list of names | transfer controls only |

## `task_groups`

```yaml
task_groups:
  appointment_flow:
    steps:
      - identify_customer
      - select_appointment
    context_scope: shared
    then: return
    merge: results
```

| Field | Values |
|---|---|
| `steps` | task names, in order, at least one |
| `context_scope` | `shared` or `isolated` |
| `then` | `return`, `transfer`, or `end` |
| `then_target` | an agent name, required with `transfer`, illegal otherwise |
| `merge` | `results`; omitted also means `results` |

When a task runs inside a group, the group's `context_scope` governs it. The
member task's own `context` does not override the group.

## `controls`

Everything the model can trigger besides a tool. One `kind` per control.

```yaml
controls:
  check_customer:
    kind: delegate
    task: customer_record
    when: Identify the caller first.
    assign:
      customer_id: result.customer_id
```

| Kind | Fields |
|---|---|
| `delegate` | `task` or `group`, `when`, `assign` |
| `agent_transfer` | `to`, `when`, `announce`, `context`, `requires` |
| `human_transfer` | `when`, and exactly one of `cold:` or `warm:` |

A delegate needs exactly one of `task` or `group`. `assign` is legal only when
delegating to one task, because each mapping reads `result.<field>` from that
task.

An `agent_transfer.context` block needs both `history` and `variables`. The
`variables` value is `all` or a non-empty list of declared variable names.

For `agent_transfer`, `announce` is optional exact spoken text. It is not a
model instruction: write the short sentence the caller should hear. Omit it
for a silent handoff.

A human transfer names its shape with a block, so a warm only field cannot be
written on a cold transfer:

| Block | Fields |
|---|---|
| `cold` | `destination`, `ring_timeout`, `on_unavailable` |
| `warm` | `destination`, `briefing`, `ring_timeout`, `on_unavailable` |

`on_unavailable` is `return_to_caller` or `hangup`; omitted means
`return_to_caller`. `ring_timeout` must be a positive Go duration. When omitted,
Pipecat uses 25 seconds. LiveKit leaves the value unset, so the LiveKit platform
default applies.
Pipecat `cloud-websocket` requires explicit `on_unavailable: hangup`; it cannot
reconnect the original media stream.
`destination` is a symbol resolved in the top level
[`destinations:`](#destinations) map above.

Whether a route can carry the shape you asked for is decided by the connection.
A warm transfer is supported only on LiveKit `sip`; Unmute does not support warm
transfer on any Pipecat target.
A warm transfer on a route with no leg to move is refused by name:

```text wrap
pipecat: telephony warm_transfer: telephony route (pipecat, cloud-websocket, twilio) does
  not emit warm transfer: a warm handoff has to act on how the destination's leg ended,
  which on this route needs a callback endpoint you host, and hosting nothing is what
  this route is for; warm transfer compiles on (livekit, sip) trunks today. Connection
  "twilio_voice" declares transport: cloud-websocket
```

## `tools`

```yaml
tools:
  - check_availability
  - end_call
```

Which `tools/<name>.yaml` files to load. Availability is decided by the `tools`
list on each agent and task.

This top-level list and every agent or task list contain names only.
**Define each tool once.** Put its full contract in `tools/<name>.yaml`; never
inline `description`, `input`, `output`, `inject`, or an execution block under
a `tools:` list in `agent.yaml`.

### Tool files

One file per tool, in `tools/`. The top level is the contract with the model;
exactly one execution block says how it runs.

| Field | What it is |
|---|---|
| `description` | what the model reads |
| `input` | JSON Schema of the parameters the model fills; required except on `builtin` and `mcp`, where it is illegal |
| `output` | optional author-side JSON Schema of the result; illegal on `builtin` and `mcp`, and elsewhere not sent to the model, not emitted in the compile report, and not enforced at run time |
| `inject` | hidden scalar arguments; string values may carry `{{variables}}`; legal on `webhook` and `local` |
| `interruption` | `provider_default`, `continue`, `cancel` |
| `effect` | `returns_data`, `ends_conversation` |
| `announce` | one fixed sentence spoken as the tool starts; no `{{variables}}`; legal on `webhook` and `local`; absent means nothing is spoken |

| Execution block | Fields |
|---|---|
| `local` | optional `handler`; omitted means `tools/<tool-name>.py` |
| `webhook` | required `url_env`; optional `path` and `auth`; a non-empty path starts with `/` |
| `mcp` | required `url_env`; optional `transport`, `auth`, and non-empty unique `tools` entries |
| `builtin` | required `id`; optional `instructions` |
| `client` | no fields; write `client: {}`; gated on every target today |
| `provider_hosted` | no fields; write `provider_hosted: {}`; gated on every target today |

An `mcp` file is the block and nothing else. The seven contract fields above are
all illegal on one, because the server describes its own tools.

| Field | Values |
|---|---|
| `transport` | `sse` or `streamable_http` |

Builtin ids: `end_call`.

`webhook.auth`:

| Field | What it is |
|---|---|
| `type` | `bearer` or `api_key` |
| `token_env` | environment variable holding the token |
| `header` | header name, `api_key` only, defaults to `X-API-Key` |

## `conversation`

```yaml
conversation:
  greeting:
    speaks_first: agent
    text: "Hi, how can I help?"
  interruption:
    enabled: true
```

| Field | Values |
|---|---|
| `greeting.speaks_first` | `agent` or `user` |
| `greeting.text` | the opening line, requires `speaks_first: agent` |
| `interruption.enabled` | required when `interruption` is present |
| `interruption.minimum_words` | how much speech counts as an interruption |
| `interruption.ignore_phrases` | phrases that do not interrupt |
| `inactivity.nudge_after`, `inactivity.end_after` | durations |
| `max_duration` | a duration |
| `thinking_audio` | `none` or `subtle` |

## `tracing`

```yaml
tracing:
  provider: langfuse
```

`provider` takes one of two values, `langfuse` or `coval`. Tracing works on the
`pipecat` and `livekit` targets and is refused on `vapi` and `deepgram`.

| Provider | Required environment names |
|---|---|
| `langfuse` | `LANGFUSE_BASE_URL`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` |
| `coval` | `COVAL_API_KEY` |

LiveKit uses the room name as the Langfuse session ID. Pipecat uses the runner
session ID as both its conversation ID and the Langfuse session ID.
Pipecat tracing owns the process OpenTelemetry provider and startup fails if another SDK provider is installed first.

With `coval`, each trace is attached to the Coval simulation that placed the
call, and the agent finds that simulation ID on the call itself. See
[tracing](/tracing/overview) for how the ID reaches the agent on each target.

Traces can contain caller speech, model input and output, and tool arguments and results.
Use only fake identities and fake customer data for release tests. Use a separate
project on your tracing provider for those tests, and do not send real customer
data until its access and retention rules are approved.

## `channels`

```yaml
channels:
  web:
    kind: realtime_audio
  phone:
    kind: telephony
    inbound: true
    outbound: true
```

| Field | Required | Values and constraints |
|---|---|---|
| `kind` | yes | `realtime_audio` or `telephony` |
| `inbound`, `outbound` | for `telephony` | `true` or `false`; at least one must be `true`; illegal on `realtime_audio` |
| `required_controls` | no | `cold_transfer`, `warm_transfer`, `dtmf_send`, `dtmf_receive`, `hold`, `hangup`, `voicemail_detection`, or `ivr_navigation`; illegal on `realtime_audio` |
| `on_voicemail` | no | `hangup` or `leave_message`; requires `kind: telephony` and `outbound: true` |

### Three rules a telephony channel brings with it

All three are enforced, fail validation, and are easier to read here than to
meet by trial and error.

**At least one direction must be enabled.** A channel with both `inbound: false`
and `outbound: false` has no call leg and is refused.

**A warm transfer needs `outbound: true`.** A warm transfer dials the
destination itself, so the agent places a call, and a channel that only receives
them cannot:

```text
channel "phone" needs outbound: true; a warm transfer places a call to its destination
```

Write `outbound: true` even on a line people only ring in on. It describes what
the agent does, not what the number is for.

**`capacity.peak_starts_per_second` becomes required.** The moment any channel
is `telephony`, the field stops being optional and must be positive:

```text
capacity.peak_starts_per_second must be positive for telephony
```

Calls arrive in bursts and each one starts a session, so a rate is the number
the compiler sizes workers from. One is a fine answer for a first line.

## `capacity`

Capacity is required for every code target, including both targets documented
on this site. A telephony channel also makes `peak_starts_per_second` required.

| Key | Required | What it is |
|---|---|---|
| `capacity` | for telephony or code targets | your traffic estimate |

```yaml
capacity:
  peak_sessions: 5
  max_sessions: 10
  avg_session_duration: 5m
```

| Field | What it is |
|---|---|
| `peak_sessions` | expected concurrent sessions at peak; must be positive |
| `max_sessions` | the ceiling you want to support; must be positive and at least `peak_sessions` |
| `peak_starts_per_second` | how fast calls arrive at peak. **Required and positive** as soon as any channel is `telephony`; optional otherwise |
| `avg_session_duration` | a positive Go duration, for example `5m` |

The compiler turns these into worker and quota numbers, marked
`[unbenchmarked]`.

## Reachability

Models are a palette, so an unused model entry is legal. Other declarations must
be reachable from `entry_agent`. An unused control, destination, tool, task,
task group, or non-entry agent is a build error. Attach it to the reachable graph
or remove it.
