`unmute init my-agent` writes a working package and asks nothing. Add
`--from-manifest` when the new package has to follow a contract your
organization saved on this computer.

## With a name

```sh
unmute init my-agent
```

```text
created my-agent/agent.yaml
created my-agent/.env.example
created my-agent/.gitignore
created my-agent/instructions.md
created my-agent/targets.yaml
created my-agent/tools/end_call.yaml
```

The name is also the directory. Each created file is printed. `cd` into it and
`validate`, `compile` and `dev` all run with no argument.

This is the whole command. It reads nothing saved on your computer and asks no
questions, so the same six files appear every time.

## For another target

```sh
unmute init my-relay --target twilio
```

`--target` takes `livekit`, `pipecat`, `slng` or `twilio`. It writes the
starter the console writes after you pick that target, and still asks nothing.
For `twilio` that is one inbound phone channel, Deepgram and ElevenLabs inside
ConversationRelay, an OpenAI model, and `connections/phone.yaml` with the four
`TWILIO_*` names. See [the Twilio target](/targets/twilio).

`--target` needs a name, and it cannot be combined with `--from-manifest`,
because a manifest picks the target itself.

## With no name

In a terminal, `unmute init` with no argument opens an interactive console. It
asks for the name, the models and the target, and it can validate and compile
the result for you.

Pick a phone route there and the scaffold writes one more file,
`connections/<name>.yaml`, holding the transport, the carrier and the
environment variable names that route needs. The target only names it. See
[`connections/<name>.yaml`](/reference/connections-yaml).

Outside a terminal, a name is required:

```text
unmute: agent name required
```

## From a saved manifest

A manifest is your organization's list of allowed models, languages, regions,
targets, tools and tracing. `--from-manifest` opens a picker of the contracts
saved on this computer, then guides the package through the choices the chosen
one allows:

```sh
unmute init hotel-agent --from-manifest
```

The picker lists the default first. The chosen file is copied into the package
as `manifest.yaml`, comments included, and `agent.yaml` names that copy. Validation
and compilation read the copy, so another computer needs nothing saved. Editing
the saved contract later does not change a package already created.

This flag is the only way a contract reaches a new package. Plain
`unmute init <name>` writes the starter scaffold even when a default is saved.
The picker needs a terminal, so a coding assistant cannot run it: create the
package yourself, then ask the assistant to complete it. See
[Company manifests](/reference/manifest) for what a contract holds and
[`unmute manifest`](/reference/cli/manifest) for saving one.

Guided setup cannot collect a custom model endpoint or a SLNG Context Router
upstream, so it leaves those bindings out of the offered choices. Write them by
hand afterwards, following the relevant [model reference](/models/llm).

## It never writes into an occupied directory

```text
unmute: init my-agent: my-agent: directory already exists and is not empty
```

## What the scaffold contains

| File | What it is |
|---|---|
| `agent.yaml` | the agent: models, one agent, greeting, channel, capacity |
| `instructions.md` | the agent's prompt |
| `targets.yaml` | one target |
| `tools/end_call.yaml` | a built in tool so the agent can hang up |
| `.env.example` | starter keys for the scaffolded target |
| `.gitignore` | keeps `.env` and `build/` out of git |

The scaffold binds SLNG speech models and an OpenAI reasoning model, so one
`SLNG_API_KEY` covers speech to text and text to speech. The starter prompt is a
real one, and it is meant to be replaced.

## The scaffolded target

The target is **LiveKit Agents**, so `targets.yaml` holds one instance named
`livekit`, `agent.yaml` carries a matching LiveKit turn detector, and
`unmute compile` writes `build/livekit/`. Pipecat is equally supported. Pick it
with `--target pipecat` or in the interactive console, or edit the package by hand as
[Targets](/targets/overview) describes.

```yaml targets.yaml
targets:
  livekit:
    provider: livekit
    version: "1.8.1"
    sdk_language: python
```

`.env.example` lists the two values you supply:

```text
OPENAI_API_KEY=
SLNG_API_KEY=
```

The LiveKit worker also needs `LIVEKIT_URL`, `LIVEKIT_API_KEY` and
`LIVEKIT_API_SECRET`, but they are not values you fill in. `unmute dev` supplies
them locally; LiveKit Cloud or a self-hosted operator supplies them at deploy
time. They remain in `compile-report.json` and the runtime startup checks.

<Note>
  The top level `.env.example` is a starter list. After `unmute compile`,
  `build/<target>/.env.example` lists the values you supply for that target;
  `compile-report.json` lists every required environment name.
</Note>

## Command reference

```text Terminal — unmute init --help
$ unmute init --help
Scaffold a new v1 agent package.

Usage:
  unmute init [name] [flags]

Flags:
      --from-manifest   Choose a saved organization manifest.
  -h, --help            help for init
      --target string   Scaffold for this target (livekit, pipecat, slng or twilio) without the wizard.
```

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Creation asks about a manifest | `--from-manifest` was passed, or you ran the `unmute` console with a saved default | Run `unmute init <name>` for the starter package |
| `no saved manifests` | `--from-manifest` with an empty library | Save one with `unmute manifest create`, or drop the flag |
| `configured default: read manifest ...` | The saved default names a manifest that is missing or invalid | Repair it with `unmute manifest edit <name> --editor`, or select another in the picker |
| `manifest initialization needs an interactive terminal` | `--from-manifest` in a script or CI | Create the package in a terminal, or use plain `unmute init <name>` |
| `agent name required` | No name outside a terminal | Pass the name |
| `--target "..." is not a target` | A value outside the four targets | Use `livekit`, `pipecat`, `slng` or `twilio` |
| The destination is not empty | The package already exists | Complete those files, or choose a fresh directory |
