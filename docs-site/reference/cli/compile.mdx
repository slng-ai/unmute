```text
$ unmute compile --help
Compile a v1 agent package to its resolved target artifacts.

With no package-dir, the package is the current directory, so you can cd into an agent and run this with no arguments.

Usage:
  unmute compile [package-dir] [flags]

Flags:
  -h, --help             help for compile
      --target strings   target instance name (repeatable; default: all)
```

## Usage

```sh
unmute compile my-agent
```

Every file written is printed. This is a package scaffolded by
[`unmute init`](/reference/cli/init), which declares one LiveKit target:

```text
generated my-agent/build/livekit/.dockerignore
generated my-agent/build/livekit/.env.example
generated my-agent/build/livekit/Dockerfile
generated my-agent/build/livekit/README.md
generated my-agent/build/livekit/agent.py
generated my-agent/build/livekit/compile-report.json
generated my-agent/build/livekit/compose.dev.yaml
generated my-agent/build/livekit/dev_metrics.py
generated my-agent/build/livekit/pyproject.toml
```

A package with tools, knowledge files, tracing, or a phone route writes more:
`tools/<name>.py` per tool, `knowledge.py`, `tracing.py`, and on Pipecat
`pcc-deploy.toml`.

Output goes to `<package>/build/<target-instance-name>/`. With no `--target`,
every declared target is compiled. `--target` is repeatable.

## The report

After the files, the compiler prints what it decided. Every line is prefixed
with the target instance name.

**Bindings.** What each model role resolved to, and the honest note that the
model string is not checked:

```text
pipecat: binding listen provider=slng model=deepgram/nova:3 (forwarded as-is, not validated)
pipecat: binding turn provider=local model=silero (forwarded as-is, not validated)
pipecat: binding speak.voice provider=slng model=deepgram/aura:2 voice=aura-2-thalia-en (forwarded as-is, not validated)
pipecat: binding reason.reasoning provider=openai model=gpt-5.6-terra (forwarded as-is, not validated)
pipecat:   param temperature=0.2
```

A LiveKit OpenAI Responses binding is the narrow exception. Its report names
the compiler directive and the transformed reasoning setting instead of
claiming that every param was forwarded unchanged:

```text
livekit: binding reason.reasoning provider=openai model=gpt-5.6-terra (OpenAI Responses mode; api is consumed and reasoning_effort is lowered when present)
livekit:   param api=responses (compiler directive)
livekit:   param reasoning_effort=low (lowered to reasoning.effort)
livekit:   param use_websocket=false (forwarded as-is, not validated)
```

**Sizing.** Your `capacity:` block turned into numbers, tagged with the
assumption they came from:

```text wrap
pipecat: sizing workers=10 [unbenchmarked] (2026-07-15 conservative 1 session per worker/GPU; channels=realtime_audio)
pipecat: sizing provider_concurrency_quota.realtime_audio=5 [unbenchmarked] (2026-07-15 conservative 1 session per worker/GPU; channels=realtime_audio)
```

**Telephony.** Present only for a target with a phone route: the resolved
route, the endpoints, every required environment variable, and an evidence line
per capability:

```text wrap
livekit: telephony route provider=livekit transport=sip carrier=twilio coordination=shared admission=livekit_dispatch
livekit: telephony required env SIP_TRUNK_HOSTNAME
livekit: telephony evidence inbound=provisional docs=https://docs.livekit.io/telephony/start/providers/twilio/ smoke=false
```

`provisional` means implemented and compiling, with no credentialed test in CI.
`smoke=false` says the same thing in the machine readable half.

The same information is written to `build/<target>/compile-report.json`.

## Warnings

Warnings print first, on standard error, and do not change the exit code:

```text
warning: livekit: LiveKit turn placement is a preference
```

## Compiling is safe to repeat

`build/` is output. Compile as often as you like; never edit inside it.
