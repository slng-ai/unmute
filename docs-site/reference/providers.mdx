A `provider:` in your `models` block names an integration the framework already
ships. Unmute never hosts integration code, so the lists below are exactly what
each framework can construct.

**SLNG is first in every list it appears in**, because the shipped examples are
built on SLNG speech models and one `SLNG_API_KEY` covers both of them.

<Info>
  Model ids and voice ids are forwarded to the vendor exactly as you write them.
  Unmute keeps no allowlist of models, so a typo surfaces as a provider error at
  run time. The compile report says so on every binding:
  `(forwarded as-is, not validated)`.
</Info>

## SLNG models

These are the only exact model ids the docs name, because they are the ones the
shipped examples and `unmute init` use:

| Role | `model:` | `voice:` |
|---|---|---|
| listen | `slng/deepgram/nova:3-en` | not used |
| speak | `slng/deepgram/aura:2-en` | `aura-2-thalia-en` |

The full SLNG catalog, with languages, hosting, and latency, is at
[docs.slng.ai/models](https://docs.slng.ai/models). Any id from there goes in
`model:` as written.

## The differences that matter

- **Speech to text**: Pipecat has `openai`, LiveKit has `sarvam`. Otherwise the
  lists match.
- **Text to speech**: Pipecat has `openai`, LiveKit has `gemini`. Otherwise the
  lists match.
- **Reasoning**: the lists differ a lot. LiveKit adds `aws` and `azure` and
  `sarvam`; Pipecat adds `deepseek`, `google`, and `qwen`. LiveKit spells the
  Mistral integration `mistralai`.

## Providers that are not listed

The two targets answer this differently.

**On Pipecat**, an unlisted provider is legal for any of the three roles on one
condition: it has to be a genuinely OpenAI-compatible endpoint, named with
`endpoint_env`.

```yaml
models:
  think:
    house_model:
      provider: my-gateway
      model: my-model
      endpoint_env: MY_GATEWAY_URL
```

Without `endpoint_env` it is refused, and the error lists what that role does
take:

```
pipecat reason binding provider "my-gateway" has no slot; reason providers on pipecat: anthropic, deepseek, google, groq, mistral, openai, openrouter, qwen; an unlisted provider needs endpoint_env (an OpenAI-compatible endpoint)
```

**On LiveKit**, an unlisted reasoning provider routes through LiveKit
Inference: managed models billed through LiveKit Cloud, with no provider key of
their own. That path needs `LIVEKIT_API_KEY` and `LIVEKIT_API_SECRET`, even in
console mode. Writing `provider: livekit` passes your model string through
verbatim.

LiveKit speech to text and text to speech have no fallback at all. Those two
lists are closed.

## Turn detection

Turn detection is not a catalog vendor slot. It is a `models.turn` binding
forwarded to the runtime:

```yaml
  turn:
    detector:
      provider: local
      model: silero
```

Every shipped example uses local Silero on Pipecat and LiveKit's own model on
LiveKit, set as a per target override:

```yaml targets.yaml
    models:
      detector:
        provider: livekit
        model: turn-detector-mini
```

`unmute validate` warns on LiveKit that turn placement is a preference there.
