`targets.yaml` says where the agent runs. Nothing about the agent's behavior
belongs here.

```yaml targets.yaml
targets:
  pipecat:
    provider: pipecat
    version: "1.7.0"

  livekit:
    provider: livekit
    version: "1.6.10"
    sdk_language: python
    models:
      detector:
        provider: livekit
        model: turn-detector-mini
```

## All keys

| Key | Type | Required | Default | Allowed values | Meaning |
|---|---|---|---|---|---|
| `targets` | map | yes | — | one or more target instance names | target definitions selected by `--target` |
| `targets.<name>.provider` | string | yes | — | `livekit`, `pipecat` | target provider |
| `targets.<name>.version` | string | for code targets | — | exact `x.y.z` in the supported window for LiveKit and Pipecat | framework version pinned in an emitted project |
| `targets.<name>.pins` | map of strings | no | — | known LiveKit package names to semantic versions | LiveKit package overrides; other providers do not consume them |
| `targets.<name>.sdk_language` | string | no | — | `python` when written | SDK used by an emitted project |
| `targets.<name>.connection` | string | for LiveKit or Pipecat telephony | — | connection file stem | this target's phone route; illegal when the package has no phone use |
| `targets.<name>.deployment_region` | string or list of strings | no | — | non-empty platform region names, with no duplicates | deployment regions; more than one is LiveKit only |
| `targets.<name>.models` | map | no | — | existing model entry names to model definitions | per-target model overrides |

The map key is the **target instance name**. It is what `--target` takes and
what names the output directory, `build/<name>/`. Two targets may use the same
provider with different settings, for example `pipecat_twilio` and
`pipecat_telnyx`.

That is the whole list. `unmute validate` accepts all four provider values so a
package can be checked for portability. `unmute compile` emits a project only
for `livekit` and `pipecat` today. A target says where the agent runs and, for a
phone agent, which one connection carries the call.

`deepgram` is classified as a code target, so validation requires a non-empty
`version` even though this release emits no Deepgram project. There is no
Deepgram version window in this release; compile refuses the missing driver.

## Framework versions are exact

For LiveKit and Pipecat, write all three numbers, such as `1.7.0`. Unmute installs
exactly what the target declares. It never widens the pin or silently upgrades it
for a feature.

This Unmute release supports exactly `livekit-agents` 1.6.10 and
exactly `pipecat-ai` 1.7.0. Any other version is refused.

## Deployment regions

`deployment_region` accepts one region or a list. Pipecat accepts exactly one;
deploying there again means another target and agent name. LiveKit emits one
`lk agent create --region` command per declared region. A LiveKit region is
chosen when the agent is created and cannot be changed in place.

Region names use the platform's vocabulary and are forwarded as written. A
model endpoint's region is separate and stays in that model's `params` or
`endpoint_env`. See [regional infrastructure](/optimization/regional-infrastructure)
for complete worker, STT, and TTS examples plus LiveKit media guidance.

An empty list entry or duplicate region is an error. Region names themselves use
the platform's vocabulary and are otherwise passed through.

## Package pins

`pins` is a LiveKit-only escape hatch for packages already known to the LiveKit
driver. Unknown package names and versions below the catalogue floor are errors.
Pipecat and the validation-only providers do not consume this map, so leave it
out for them.

## models overrides

```yaml
    models:
      detector:
        provider: livekit
        model: turn-detector-mini
```

Keyed by the entry name from `agent.yaml`, and taking the same fields as an
entry there. Use it when a target cannot run an entry as defined, or runs its
own better.

## The phone route is not here

A target names one connection and declares nothing else about how a call reaches
it:

```yaml targets.yaml
targets:
  livekit:
    provider: livekit
    version: "1.6.10"
    sdk_language: python
    connection: twilio_sip
```

The mechanism, the carrier, and the account credentials live in that one file.
See [`connections/<name>.yaml`](/reference/connections-yaml).

Three fields used to sit on the target. Writing any of them here is refused, and
the refusal names the new home:

```text
targets.yaml:6: target "livekit" declares transport: sip, which now belongs in
  connections/twilio_sip.yaml. A target names one connection and the connection
  declares the route
```

```text
targets.yaml:6: target "livekit" declares carrier: twilio, which now belongs in
  connections/twilio_sip.yaml alongside its transport
```

```text
targets.yaml:7: target "livekit" declares destinations, which now belong at the top
  level of agent.yaml. A destination is who this agent escalates to, which is the same
  desk whichever carrier reaches it
```

Where the target names no connection, the first two messages say
`in the connection file this target should name` instead of a file name.
