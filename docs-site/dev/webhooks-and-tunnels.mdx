title: "Webhooks and tunnels"
description: "How the public URL is made, how to bring your own, and how to keep the CLI away from your carrier settings."
---

Routes where the carrier calls the local agent over HTTPS or WSS need a public
HTTPS address. By default `unmute dev --telephony` makes one and temporarily
points supported carrier numbers at it. You can bring your own URL or leave the
number untouched.

## The managed tunnel

With no `--public-url`, the command needs `cloudflared` on your PATH. It starts
a quick tunnel against the local agent port, reads the assigned origin, and
hands that origin to the local runtime. Compose callback routes receive it as
`UNMUTE_PUBLIC_URL`; Pipecat `cloud-websocket` passes its host to the local
Pipecat runner.

```text
pipecat: managed tunnel https://random-words-here.trycloudflare.com (quick tunnel URLs rotate on every run)
```

Rotating is why the carrier webhook is reconfigured on every start.

If `cloudflared` is missing:

```text wrap
cloudflared not found on PATH; the managed tunnel for carrier webhook routes needs it. Install it (macOS: `brew install cloudflared`; Linux: distribution package or a binary from https://github.com/cloudflare/cloudflared/releases) or pass --public-url to bring your own tunnel (ngrok included)
```

cloudflared is the only tunnel client the CLI manages. It is Apache 2.0
licensed and needs no account for quick tunnels, so one client means one output
parser and one failure mode. Any other tunnel is welcome; you run it and pass
its origin.

<Note>
  LiveKit SIP needs carrier reachable SIP signalling and RTP media, not HTTPS.
  A tunnel is neither required nor sufficient there, so that route starts no
  tunnel at all.
</Note>

## Bring your own URL

```sh
unmute dev ./agent --telephony --public-url https://your-tunnel.example
```

`--public-url` skips tunnel management entirely. It must be an HTTPS origin,
with an optional path, and nothing else:

```text
unmute: dev examples/twilio-telephony-hello: --public-url must be an HTTPS origin with an optional path, got "http://x.example"
```

A trailing slash is trimmed for you. `--public-url` requires `--telephony`:

```text
unmute: dev: --public-url requires --telephony
```

With the origin known, the command prints the exact callback URLs the carrier
should use, one line each, for example the media websocket, the outbound
trigger, and the status callback. Your URL must already forward to the port set
by `--bot-port`, which defaults to `7860`.

The inbound webhook path is route-specific:

| Local route | Twilio voice webhook |
|---|---|
| Pipecat `cloud-websocket` | `POST /` |
| Pipecat `carrier-websocket` | `POST /telephony/inbound` |
| LiveKit `connector` | `POST /telephony/inbound` |

LiveKit SIP is not in this table because an HTTPS origin cannot expose SIP or
RTP.

## Leave the carrier alone

By default, on carriers that support it, the CLI sets the number's voice
webhook to the route's exact inbound URL and prints the previous value. For a
generated callback application:

```text wrap
pipecat: Twilio voice webhook for +15551234567 set to https://random-words-here.trycloudflare.com/telephony/inbound (was: https://example.com/old)
```

Pipecat `cloud-websocket` instead sets it to the origin root, such as
`https://random-words-here.trycloudflare.com/`, because the local Pipecat runner
answers `POST /` itself.

On exit it puts the old value back:

```text
pipecat: Twilio voice webhook for +15551234567 restored to https://example.com/old
```

That undo matters. A dev URL dies with the process, so leaving it on a real
phone line would aim that line at a dead tunnel.

To keep the CLI away from your carrier settings:

```sh
unmute dev ./agent --telephony --no-webhook
```

```text
pipecat: --no-webhook, carrier number left untouched; point it at https://random-words-here.trycloudflare.com/ yourself
```

Then point the number at the exact inbound URL printed for the route. For
Pipecat `cloud-websocket`, that is the origin root. `--no-webhook` requires
`--telephony`.

Use it when the number is shared, when your carrier is configured by
infrastructure code, or when you simply want no outward change made for you.

## What the CLI never does

- It does not buy or create carrier resources.
- It does not touch a TwiML Bin or any static markup you own.
- It does not install a tunnel client for you.
- It does not leave a webhook pointing at a finished run.
