<Note>
  Choosing a transcriber for **speed** rather than accuracy score is its own decision, and it is measured in [Optimizing your agent](/optimization/overview): how fast a model lands its *final* transcript decides how long the caller waits.
</Note>

The `listen` role turns the caller's voice into text. You bind it once in
`agent.yaml`:

```yaml agent.yaml
models:
  listen:
    transcriber:
      provider: slng
      model: "deepgram/nova:3"
```

A scaffolded package binds SLNG here by design, so one `SLNG_API_KEY` covers
listening and speaking. See the [SLNG Execution Layer](/optimization/execution-layer).
To keep transcription compute in a world part or exact region, see
[regional infrastructure](/optimization/regional-infrastructure).

<Info>
  Model ids are forwarded to the vendor exactly as you write them. Unmute keeps no
  allowlist, so a typo surfaces as a provider error at run time.
  `build/<target>/compile-report.json` records this on every binding as
  `forwarded as-is, not validated`.
</Info>

## The SLNG models this repository uses

| Where | `model:` |
|---|---|
| `unmute init`, and every example except `slng-support` | `deepgram/nova:3` |
| `slng-support`, which compiles to the `slng` target | `slng/deepgram/nova:3-en` |

Those are the only exact ids the docs name, because they are the ones the examples
run. The full SLNG catalog, with languages, regions, and hosting, is at
[docs.slng.ai/models](https://docs.slng.ai/models); any id from there goes in
`model:` as written.

### Why two shapes, and which one to pick

The `slng/` prefix selects a model SLNG hosts itself. An id without it, like
`deepgram/nova:3`, is the same vendor model reached through SLNG as a proxy. Both
are one binding and one `SLNG_API_KEY`; the difference is who runs the model and
how it is billed, which
[docs.slng.ai](https://docs.slng.ai/execution-layer/byok) covers.

For **listening**, the two are not equally fast, and the gap is larger than most
settings on the optimization pages. Measured against the live bridge in August
2026, time from end of speech to the final transcript:

| route | median | samples |
|---|---|---|
| `deepgram/nova:3` | 280ms | 13 |
| `slng/deepgram/nova:3-en` | 605ms | 16 |

The caller waits through that on every turn, which is why the scaffold and the
examples take the proxied route. Two caveats before you read too much into it:
those sample counts are small, and a hosted id is not offered in every world
part, so a region you need may decide this for you. Measure your own route rather
than trusting the table, as
[Optimizing your agent](/optimization/overview) says of every number on it.

## Pipecat

| Provider | Notes |
|---|---|
| `slng` | SLNG hosted speech to text. `SLNG_API_KEY`. |
| `assemblyai` | |
| `cartesia` | |
| `deepgram` | |
| `elevenlabs` | also accepted as `eleven_labs` |
| `gradium` | |
| `openai` | |
| `soniox` | |
| `speechmatics` | |

An unlisted provider is legal on Pipecat on one condition: it has to be a
genuinely OpenAI-compatible endpoint, named with `endpoint_env`. Without that it is
refused, and the message lists what the role does take.

This list is closed. LiveKit speech to text has no fallback path, so a provider
that is not here cannot be bound at all.

## The difference between the two

Pipecat has `openai`, LiveKit has `sarvam`. Everything else matches.
