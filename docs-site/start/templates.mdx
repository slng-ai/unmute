A template is a finished voice agent you can run today. Every template is a
full Unmute package: the agent file, the prompt, the tools, and the targets it
compiles to.

Templates live in their own repository:
[**slng-ai/unmute-templates**](https://github.com/slng-ai/unmute-templates).

On this page:

- [Run one](#run-one) - clone, validate, talk to it
- [Pick one](#pick-one) - where the list lives
- [Make it your own](#make-it-your-own) - copy and rename
- [Templates and examples](#templates-and-examples) - which is which
- [Contribute a template](#contribute-a-template) - what a good one carries

## Run one

```sh
git clone https://github.com/slng-ai/unmute-templates
cd unmute-templates

unmute validate single-prompt              # check the files
unmute compile single-prompt               # write the projects
unmute dev single-prompt --target pipecat  # talk to it in your browser
```

Each command takes the folder name of the template you want.

Every template needs API keys. Put them in a `.env` file, either at the root of
the clone or inside the template folder you are running. The
[secrets guide](/reference/secrets) explains which names belong to the package
and which belong to its runtime. You need the `unmute` binary first, which the
[installation page](/start/installation) covers.

## Make it your own

Copy the folder and change the name inside it.

```sh
cp -r single-prompt my-agent
```

Open `my-agent/agent.yaml` and change the `name:` line. Unmute names the
deployment after it, so two agents that share a name overwrite each other.

From there, [how a package fits together](/build/how-a-package-fits-together)
explains every file you are looking at.

## Templates and examples

Both are working packages. They answer different questions.

| | Templates | Examples |
|---|---|---|
| Where | [slng-ai/unmute-templates](https://github.com/slng-ai/unmute-templates) | the `examples/` folder of [slng-ai/unmute](https://github.com/slng-ai/unmute) |
| For | starting a real agent | reading, and proving a feature works |
| Shape | one agent per use case, ready to copy | one package per feature of the compiler |

If you want to start building, take a template. If you want to see how one key
behaves, read an example.

## Contribute a template

A template is welcome from anyone. It is a smaller commitment than a code
change, because it adds no keys and changes no behaviour.

Open your pull request on
[slng-ai/unmute-templates](https://github.com/slng-ai/unmute-templates), not on
the compiler repository. A good one carries five things:

1. **One folder, one idea.** Name the folder after what it shows, not after the
   company it was written for. If an existing template already shows the idea,
   improve that one instead.
2. **It validates and compiles.** Run both commands from the root of the clone
   before you push.
   ```sh
   unmute validate my-template
   unmute compile my-template
   ```
3. **A README in the folder.** Say what the agent does, what to listen for on a
   call, which keys it needs, and the command that runs it.
4. **A row in the repository README table.** Same three columns as the rows
   around it: the folder, what it shows, and the keys it needs.
5. **No secrets in the files.** Keys are read from the environment. A committed
   key is a leaked key, and it is leaked the moment the pull request opens.

Say hello on [Discord](https://discord.gg/kxZactmWj) before you start a large
one. It is the fastest way to find out whether somebody is already on it.

<Note>
  Changing what Unmute itself accepts, emits or refuses is a different job with
  a different checklist. That goes to the
  [contributing guide](/community/contributing).
</Note>
